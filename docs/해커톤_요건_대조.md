## 3. Strands 이식 — 무엇을 얼마나

**1단계 (요건 통과선)** — ✅ **완료** (`fcbb0cf`). `app/strands_agents.py` 를 새로
두고 `Agent(model=OpenAIModel(...))` + `agent.structured_output(pydantic)` 을 쓴다.
`SellerAgentPort`/`BuyerAgentPort` 덕에 `negotiate.py` 는 `_build_agents()` 분기 한
절만 늘었다. 프롬프트는 `app/agent_prompts.py` 로 빼서 두 어댑터가 공유한다 —
정보 은닉 규약이 프롬프트 문장 안에 있어서 어댑터마다 들고 있으면 조용히 깨진다.

**왕복 확인됨** (2026-09-08). `NEGOTIATOR_MODE=strands` 로 협상 한 건을 돌렸다 —
가격은 `structured_output` 으로, 메시지는 한국어 문장으로 모델에서 나왔고 라운드
상한(3회)과 정보 은닉이 로그에서 그대로 확인된다. 결과는 결렬(FAILED)인데 이건
정상 판정이다: 최저가 업체가 MOQ 3,000 미달로 스크리닝에서 빠진 뒤 남은 곳들이
상한가를 넘었다.

**2단계 (점수가 나는 곳)** — ✅ **완료** (`523d958`). `app/agent_tools.py` 가
`store.list_items()` · `store.sellers_for()` · `feasibility.check()` 를 `@tool` 로
노출하고, `app/assistant.py` 의 에이전트가 무엇을 확인할지 스스로 정해 여러 번
부른다. 화면 04 가 **무슨 도구를 몇 번 불렀는지** 배지로 보여준다 — 답만 보면
모델이 지어낸 것과 룰이 판정한 것을 구분할 수 없기 때문이다.

`intake.classify()` 는 목록에 있었으나 CRM 폐기와 함께 사라졌다
([`decisions/0005`](decisions/0005-odoo-와-제조업-도메인을-걷어낸다.md)).

**설계에서 걸린 것 둘** — 둘 다 검사로 고정했다. 배경·대안·대가는
[`decisions/0006`](decisions/0006-에이전트-도구에-정보-은닉-경계를-긋는다.md):
- `store.sellers_for()` 가 돌려주는 `SellerRegister` 에 셀러의 **최저 수용가**가
  들어 있다. 그대로 모델에 넘기면 협상이 성립하지 않아서 도구가 잘라낸다
- **협상 에이전트에게는 도구를 주지 않았다.** 셀러가 `find_sellers` 를 부르면
  경쟁 셀러의 제시가를 본다

**4단계 (추천 엔진 · 2026-09-08)** — 4안 기획이 확정되며 Strands 가 쓰이는 자리가
둘 늘었고, 심사 기준 1번에 쓸 수 있는 것은 이쪽이 더 강하다.

- **의미 대조** (`app/engine/match.py`) — 리뷰 문장이 제조사 스펙 주장에 닿는지·
  어긋나는지를 모델이 판정한다. 기획안이 *"이 기획의 심장"* 이라 부른 3단계다.
  전체 채점 1,013건 · 8분 33초. 모델이 낸 판정에서 **지어낸 review_id · 원문에
  없는 인용 · 수치 없는 근거**를 룰이 걸러낸다
- **6단계 도구 오케스트레이션** (`app/engine/run.py`) — 에이전트가 도구 5개를
  스스로 골라 부른다. `RECOMMEND_MODE=strands`

**채점기가 있다** (`scripts/eval_matcher.py`). 합성 리뷰의 정답 라벨을 기준으로
의미 대조의 정밀도·재현율과 **판정이 뒤집히는지**를 잰다. *"에이전트를 붙였다"*
가 아니라 *"붙이고 재 봤더니 얇은 표본에서 판정을 뒤집길래 가드레일을 걸었다"*
가 되는 자리라, 심사 기준 1번의 "non-trivial" 근거로 이쪽을 쓴다.

| | 처음 | 가드레일 뒤 |
|---|---|---|
| 닿음 F | 0.786 | **0.866** |
| 어긋남 F | 0.590 | **0.930** |
| 판정이 바뀐 주장 | 1 / 6 | **0 / 6** |

**3단계 (가점)**: `OpenAIModel` → `BedrockModel`, AgentCore 배포.

**남기는 것**: `agents.py` 룰 기반과 `audit.py` 감사자는 버리지 않는다. 에이전트를
감싸는 **가드레일**로 재배치하면 Design 점수에 유리하고, 데모 당일 API가 흔들려도
`rule` 모드로 같은 화면을 돌릴 수 있다.

**대가**: 새 의존성(지금은 `odoo_client.py`가 표준 라이브러리만 쓴다), Bedrock으로
가면 리전별 모델 액세스 승인 대기, 도구 호출로 라운드당 지연·비용 증가.

회의 전사 기준이라 틀린 건 아니지만, 규정상 정확히는 **9/15 09:00 KST**다.

**`LICENSE`·`README` 위치 — 재 보니 요건이 안 찼다 (2026-09-07 확인).** GitHub은
**기본 브랜치**에서 라이선스와 README를 읽는다. 제출 저장소의 기본 브랜치(`main`)에는
지금 **`README.md` 한 파일**뿐이고 내용은 `skn_final` 한 줄이다(`licenseInfo: null`).
실제 코드와 문서는 `develop`·`backend`·`front`·`reinforce`·`sllm` 에 흩어져 있다.

규정의 *"Include README"* 와 라이선스 요건이 **둘 다 여기 걸리고**, 심사자가 공개
URL로 처음 보는 화면이기도 하다. 병합 방침은 팀이 정할 일이라 여기서 정하지 않지만,
**제출 전에 기본 브랜치가 채워져야 한다는 것 자체는 선택지가 아니다.**
