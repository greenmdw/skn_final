# 개발 요청 — 서버: 확정한 주변기기의 화면 설명(스냅샷) 보관·반환 (QA 10/16 #5)

- 작성: 2026-10-18 · 대상: `peripheral` 브랜치(`src/schemas.py`, `src/services/list_service.py`, `src/repo/plan_repo.py`) · 상태: **요청**(화면은 이미 구현해 두었다)
- 짝: 화면 쪽은 `front`(`web/src/state/types.ts` `PeripheralSnapshot`, `web/src/utils/peripheralResult.ts` `snapshotOf`·`withSnapshot`)

## 한 줄 요약
**견적을 확정할 때 화면에 보이던 주변기기 설명(스펙 한 줄·요청한 조건의 근거·점수 축·사용기)을 화면이 함께 보내니, 서버는 해석하지 말고 그대로 저장했다가 리포트 응답에 돌려준다.** 그러면 "견적 수정하기"로 다시 열어도 처음 보던 모습 그대로(가격·근거도 확정 시점 그대로) 보인다. 지금은 이름·가격만 있는 자리표시 카드가 된다.

## 1. 확정 요청 (`POST /lists/{id}/confirm`)
`peripherals[]` 항목에 선택 필드 `view`를 더한다.

```json
{ "kind": "monitor", "variant_id": "…", "qty": 1,
  "view": { "v": 1, "rank": 1, "keySpecs": [...], "requested": [...], "pricePosition": {...}|null,
            "scoreAxes": [...], "feel": {...}|null, "reviewAspects": [...], "requirement": [...] } }
```

- `ConfirmPeripheralIn`에 `view: dict[str, Any] | None = None` 추가.
- **내용을 해석하지 않는다.** 화면이 쓰는 값일 뿐이라 서버가 검증할 스키마는 없다. 가격은 지금처럼 `variant_id`로 서버가 다시 조회한다(`view` 안의 값은 신뢰·계산에 쓰지 않는다).
- 안전장치: `view`가 dict가 아니거나 JSON 크기가 32KB를 넘으면 **저장하지 않고 버린다**(확정은 그대로 성공). 최상위 `v`가 정수 1이 아니어도 저장은 하되 반환 때 그대로 돌려준다(화면이 모르는 버전은 무시한다).
- 저장 위치: 주변기기 줄의 `snapshot`(JSON)에 `snapshot["view"] = view`. 새 컬럼·마이그레이션은 필요 없다.

## 2. 리포트 응답 (`GET /lists/{id}/report`)
`ReportPeripheralOut`에 `view: dict[str, Any] | None = None` 추가, `get_report`의 주변기기 줄에 `snapshot.get("view")`를 싣는다. 없으면 `null`.

## 3. 견적 수정하기
`new_revision`(복제)이 주변기기 줄을 복제한다면 `snapshot`(그 안의 `view` 포함)도 같이 복제한다. 화면은 다시 확정할 때 복원한 `view`를 그대로 다시 보낸다(서버가 복제하지 않아도 동작한다).

## 시험
- `view`를 보내 확정 → 리포트에 같은 `view`가 돌아온다.
- `view` 없이 확정 → `null`(기존 시험 유지).
- 32KB 초과·dict 아님 → 확정은 성공하고 `view`는 `null`.
- 주변기기만 확정·본체와 함께 확정 두 경로 모두.

## 화면이 이미 하는 일(확인용)
- 확정 때 큰 카드에 올린 제품의 설명을 `view`로 보낸다(다른 선택지를 골랐으면 그 제품의 설명).
- 리포트의 `view`가 모양이 맞으면(`v === 1`) 견적 수정하기로 연 카드가 스펙 한 줄·요청 항목 근거·점수 축·사용기를 보인다. 없거나 모르는 버전이면 지금처럼 이름·가격만 보인다.
