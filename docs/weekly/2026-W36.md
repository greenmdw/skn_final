### D-1. P0에 LLM을 한 줄도 넣지 않는다

| | |
|---|---|
| **쟁점** | LLM 기반 협상 플랫폼인데 MVP에 LLM을 넣을 것인가 |

| **근거** | 11시[40:42] "MVP는 룰 기반, 검증 절차 전부 제외 — 이것이 P0" / 12시[18:26] "조건 해석은 당장 LLM을 빼도 된다" / 17시[47:02] "LLM 쓰는 단계는 P1" |

| | |
|---|---|

### D-3. 할루시네이션은 LLM이 아니라 룰로 막는다

| | |
|---|---|
| **쟁점** | "재고 10대인데 100대 가능하다고 응답"(11시[14:49]) 같은 거짓 응답을 어떻게 거를 것인가 |
| **선택** | 2단 방어. ①협상 **이전** 스크리닝에서 재고·사양·납기 미달 셀러를 라운드 진입 전 제외 ②**감사자**가 LLM 출력을 floor/cap 규칙과 대조해 위반 시에만 보정하고 `audit_note`를 로그에 남김 |
| **버린 대안** | LLM에게 검증까지 맡기기 / 검증을 P1으로 미루기 |
| **근거** | v3 §2가 "룰로도 걸러진다 — LLM 없이 P0에 넣을 수 있는 유일한 검증"이라 명시. 데모에서 가장 잘 보이는 장면 |
| **뒤집힐 조건** | 규칙으로 표현 불가능한 위반 유형(사양 해석 오류 등)이 데모에서 나오면 LLM 검증자 추가 검토 |

**이번 주 팀 고유의 결론**: 감사자는 매 턴 도는 게 아니라 **위반했을 때만** 개입한다. 정상 출력은 그대로 통과 — 로그에 `audit_note`가 있으면 그 자체가 "LLM이 틀렸던 지점"의 증거가 된다.

## 4. 막힌 것 / 함정 (재발 방지)

| 증상 | 원인 | 대응 |
|---|---|---|
| `OperationalError: table ... has no column named ...` | 스키마에 필드를 추가해도 `create_all()`은 기존 테이블에 컬럼을 안 붙임 | 스키마 변경 시 `data/` 폴더 삭제 후 재기동. 이 스코프에 Alembic은 과함 |

| AWS에서 목업의 API 호출 실패 | `const API = "http://127.0.0.1:8000/api"` 하드코딩 | 상대경로 `"/api"`로 수정 완료 |
