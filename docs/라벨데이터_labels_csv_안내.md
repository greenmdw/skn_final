# `labels.csv` 안내 — 결측 페어 사유 및 축 방향

대상 파일: `outputs/persona_diagnostic_20260929/labels.csv`
관련 원본: `outputs/persona_diagnostic_20260929/raw_responses.jsonl`, `summary.md`

## 1. 일부 페어(pair03, pair07 등)가 빠져 있는 이유

`labels.csv`는 페르소나 5명이 다수결로 **"무승부"**라고 판단하거나(3명 이상 합의 실패 포함) 결론을 내지 못한 쌍은 라벨에서 제외하도록 만들어져 있습니다(`scripts/persona_priority_diagnostic.py:247-249`).

```python
final_label = _majority(votes, min_agree=3)
if final_label is None or final_label == "무승부":
    continue   # 무승부/합의실패 쌍은 라벨 없이 버림
```

실제로 `raw_responses.jsonl`을 확인하면 pair03·pair07은 5명 전원, 3회 반복 응답 모두 만장일치로 "무승부"였습니다. 원인은 두 후보의 축 값이 애초에 완전히 동일했기 때문입니다.

```
pair03 (RAM 슬롯)
A = {가격: 0.0, 성능: 0.5, 밸런스: 0.75, 리뷰: 0.5, 호환여유: 0.5, 소음: 0.5}
B = {가격: 0.0, 성능: 0.5, 밸런스: 0.75, 리뷰: 0.5, 호환여유: 0.5, 소음: 0.5}
```

**즉, 파이프라인 버그로 빠진 게 아니라 "판단 근거가 없어 정상적으로 제외된" 케이스입니다.**

### 근본 원인
RAM·케이스 등 일부 슬롯은 `stage3b_rank._score()`가 CPU/GPU/파워처럼 후보별로 세분화된 계산식을 갖고 있지 않고, 대부분의 축이 고정 기본값으로 채워집니다. 그래서 같은 슬롯에서 어떤 두 후보를 뽑아도 점수가 동일하게 나와 페르소나 입장에서도 고를 근거가 없습니다.

- 소음 축도 같은 이유로 차별화되는 슬롯이 8개 슬롯 중 CPU·GPU·쿨러 3개뿐이라, 저소음 우선순위의 라벨 수가 다른 우선순위보다 적게 나온 것도 같은 맥락입니다.

> 참고: 이 결측은 라벨 생성 스크립트의 정상 동작이지만, RAM·케이스 슬롯의 스코어링 로직 자체가 후보 간 변별력이 부족하다는 점은 별도로 개선 검토가 필요합니다.

## 2. 축 방향 — 6개 축 전부 "값이 높을수록 좋음"

`_score()`는 모든 축을 0~1로 정규화하며, 방향을 통일해 항상 1에 가까울수록 좋은 상태가 되도록 설계돼 있습니다.

| 축 | 방향 | 계산식 / 의미 |
|---|---|---|
| 가격 | 높을수록 좋음 | `max(0, 1 - 가격/슬롯예산)` — 1=예산 대비 저렴, 0=예산 초과 |
| 성능 | 높을수록 좋음 | `min(1, tier/10)` — 성능 등급이 높을수록 1에 가까움 |
| 밸런스 | 높을수록 좋음 | `1 - \|tier - 목표tier\| / 4` — 목표 성능에 가까울수록 1 |
| 리뷰 | 높을수록 좋음 | 0.25/0.5/0.75 3단계 — 평판이 좋을수록 1에 가까움 |
| 호환여유 | 높을수록 좋음 | 전력/소켓 등 여유가 클수록 1, 빠듯하면 0 |
| 소음 | 높을수록 좋음 | **1.0=매우 조용, 0.0=시끄러움** (값 자체가 "조용함 정도") |

**낮은 값이 좋은 축은 없습니다.** 다만 소음은 이름만 보면 헷갈리기 쉬운데, "소음이 높다"가 아니라 "조용함 정도가 높다"는 뜻이라 값이 클수록 좋다는 점에 유의해 주세요. (LLM 페르소나에게도 프롬프트에서 "소음은 값이 높을수록 더 조용하다"고 명시했습니다.)
