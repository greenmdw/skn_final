# 견적 리포트의 목표가 알림 기능 삭제 계획

작성일: 2026-10-18
상태: **1·2단계 구현·커밋 완료(bb9a2385), 3·5단계 구현 완료(미커밋), 4단계(기존 개발·배포 DB 정리)는 실행 전 별도 확인 대기.** D1~D3은 2026-10-18에 권장대로 확정했다. 화면(`web/`)은 이번 작업에 한해 사용자 허락(2026-10-18)을 받아 직접 고쳤다. 프론트엔드 요청 문서는 따로 만들지 않는다.

## 1. 목적

견적 리포트 화면의 "목표가 알림" 패널을 없애고, 이 패널만 쓰던 API·서비스·워커·DB 테이블·테스트·문서를 함께 지운다. 이 기능은 2026-09-30 기획서의 ACC-02 요구로 되살린 것(`db/migrations/0004_notification_events.sql`)이며, 이번에 다시 범위에서 뺀다.

> **삭제 대상은 "확정 견적의 총액을 지금 카탈로그 가격으로 다시 계산해 목표 금액과 견주고, 도달하면 메일을 보내는" 기능 전체다.** 확정 때 적는 기록용 "목표 금액"(`planning.plan_revision.target_amount`)은 남긴다.

## 2. 현재 구조 (2026-10-18 확인)

| 층 | 구성 | 비고 |

### 4단계 — 이미 만들어진 DB 정리 (5장 D2 결정 뒤)

`migrate.py`는 forward-only라서 3단계만으로는 개발 DB(`truefit`)·AWS 배포 DB의 테이블이 지워지지 않는다. 다음 SQL을 한 번 직접 실행한다.

```sql
-- 남은 데이터 확인(필요하면 먼저 백업)
SELECT count(*) FROM notification.price_watch;
SELECT count(*) FROM notification.price_watch_evaluation;
SELECT count(*) FROM notification.notification_event;

BEGIN;
DROP SCHEMA notification CASCADE;
DELETE FROM _migrations.schema_migrations WHERE version = '0004_notification_events';
COMMIT;
```

- 0000~0003은 체크섬이 바뀌어 `migrate.py status`에 `CHECKSUM MISMATCH`가 뜬다. 경고만 나고 적용은 막지 않는다. 경고를 없애려면 `schema_migrations.checksum`을 새 값으로 갱신한다(D2에서 함께 정한다).
- 테스트는 세션마다 새 DB를 만들므로 이 단계와 무관하다.
- 배포 DB는 되돌리기 어려운 작업이므로 실행 전에 따로 확인받는다.

## 5. 결정이 필요한 사항

| 번호 | 질문 | 권장 |
|---|---|---|
| D1 **확정(권장대로)** | DB 테이블까지 지우나, 코드만 지우고 테이블은 남기나 | 지운다(3단계). 테이블만 남기면 `RESTRICT` FK 때문에 알림이 걸렸던 견적은 나중에 물리 삭제가 막히고, 쓰지 않는 스키마가 계약 테스트에 계속 남는다. 다만 0004는 한 번 지웠다가 되살린 이력이 있어 팀 확인을 권한다 |
| D2 **확정(권장대로)** | 기존 DB(개발·배포)의 `notification` 스키마를 언제 지우나, 체크섬을 갱신하나 | 코드 배포 직후 4단계 SQL 실행, 체크섬도 갱신. 배포 DB는 남은 행 수를 먼저 확인한다 |
| D3 **확정(권장대로)** | 기획서 ACC-02 행을 지우나, 삭제 표기로 남기나 | 삭제 표기로 남긴다. 되살렸다 지운 이력을 추적할 수 있다 |

## 7. 위험

| 위험 | 대응 |
|---|---|
| 다른 브랜치·담당자가 `/alert`나 `price_watch`를 쓰는 작업을 진행 중일 수 있음 | 병합 전 `develop`에서 6장 grep을 다시 돌린다 |
| 기준 마이그레이션 수정은 기존 DB에 반영되지 않음 | 4단계를 배포 절차에 넣는다. 빠뜨리면 사용하지 않는 테이블이 남을 뿐 앱은 동작한다 |
| 배포 DB에 사용자가 켜 둔 알림 데이터가 있을 수 있음 | 4단계에서 행 수를 확인하고, 있으면 백업 후 삭제한다 |
| 줄 번호가 다른 작업으로 밀림 | 수정 직전에 블록 이름(`-- Name: price_watch …`)으로 다시 찾는다 |
