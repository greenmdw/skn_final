## 1. 지켜야 할 것 (모든 묶음 공통)

1. **원본 `data/parts_list_modify.xlsx`는 수정하지 않는다.** 작업 폴더에 사본을 만들어 채운다.
2. **기존 열의 값은 바꾸지 않는다.** 새 열(이미 만들어져 있는 열)만 채운다. 기존 값이 틀렸다고 판단되면 바꾸지 말고 `changes_*.csv`의 `비고`에 적는다.
3. **추정·계산 금지.** 공식 자료에 없는 수치를 계산으로 만들지 않는다(예: "TDP × 1.35"). 공식 출처에서 확인한 값만 넣는다.
4. **값마다 출처 URL을 그 행의 출처 열에 적는다.** 출처 없는 값은 넣지 않는다.
5. **표기 통일**

| 항목 | 표기 |
|---|---|
| 길이·높이·두께 | mm 숫자(`304`) |
| 전력·용량 | W·GB 숫자(`750`) |
| 메인보드 폼팩터 | `ATX` `mATX` `Mini-ITX` `E-ATX` |
| 파워 폼팩터 | `ATX` `SFX` `SFX-L` |
| 소켓 | `AM4` `AM5` `LGA1700` `LGA1851` |
| 여러 값 | 세미콜론(`120;140;240`) |
| 예/아니오 | `O` / `X` |

6. **같은 이름의 다른 제품을 섞지 않는다.** 접미사(SUPER·Ti·X3D·K/KF·용량·키트 구성)가 다르면 다른 제품이다.

## 2. 확인 방법 (여기까지 해 보고 못 찾은 것만 비운다)

정적 HTTP 요청이나 검색 결과 요약으로 끝내지 않는다. 다음을 **순서대로** 시도하고, 시도한 URL을 `미확인 사유`에 남긴다.

1. **제조사 공식 제품 페이지를 브라우저로 렌더링해서** 사양(Specifications/Tech Specs) 탭을 연다. 동적 페이지(ASUS, MSI 등)는 렌더링이 필요하다.
2. 페이지에 없으면 **제조사 사양 PDF·사용자 매뉴얼·데이터시트**를 내려받아 읽는다.
3. 그래도 없으면 **제조사 지원(Support) 페이지·CPU 지원 목록 PDF**를 확인한다.
4. 마지막으로 **공신력 있는 2차 자료**(리뷰 사이트의 제조사 발표 인용, 판매처의 제조사 사양표)를 쓰되, 이 경우 `비고`에 `2차 출처`라고 적는다.
5. 위를 다 해도 없으면 `제조사 미공개` 또는 `모델별 상이` 같은 **구체적 사유**를 적는다. "수동 확인 필요"는 사유로 인정하지 않는다.

## 3. 결과물 형식 (묶음마다)

```
outputs/<묶음ID>/
  parts_list_modify.<묶음ID>.xlsx   ← 원본 사본에 채운 것 (해당 시트만 바뀌어야 한다)
  changes_<묶음ID>.csv               ← 바뀐 셀 목록
  report_<묶음ID>.md                 ← 채움률·미확인 사유·검증 결과
```

- `changes_*.csv` 열(UTF-8 BOM): `시트, 제조사, 모델명, 열, 이전값, 새값, 출처URL, 확인일, 비고`
- `report_*.md`: 열별 `채움 N/전체`, 못 채운 행과 사유(§2의 시도 URL), 아래 **품질 검증** 결과.
- **품질 검증(필수)**: 새로 채운 값 중 **무작위 10%(최소 5건)를 공식 페이지에서 다시 열어** 일치하는지 확인하고 일치율을 보고한다. 일치율이 90% 미만이면 그 묶음 전체를 다시 확인한다.
- `outputs/`에는 결과물만 둔다. `node_modules`, 검사용 덤프(`*.ndjson`), 스크립트는 넣지 않는다.

## 4. 작업 묶음

권장 순서: **B1 → B2 → B3 → B4 → B5 → B6 → B7 → B8 → B9~B11**. 앞 묶음이 호환 검사에 직접 쓰인다.

---

### B1. 파워(PSU) 40종 — 길이·PCIe 커넥터 개수
- 시트 `PSU`. 채울 열: `길이(mm)` · `PCIe 8핀 개수` · `12V-2x6 개수`(이미 40행 채워져 있음 → **재검증 대상**) · 출처는 `길이·커넥터 출처 URL`.
- 행: 40행 전부. 제조사 분포: FSP 6, Corsair 5, Micronics 4, be quiet! 3, SuperFlower 3, Zalman 3, 그 외.
- `PCIe 8핀 개수`는 파워가 **기본 제공하는 PCIe 6+2핀 케이블의 커넥터 총 개수**로 센다(케이블 수가 아니라 커넥터 수). 제조사 사양표의 `PCIe connector` 항목을 쓴다.
- `12V-2x6 개수` 기존 값(0 또는 1)이 공식 사양과 일치하는지 **전수 재검증**한다. 다르면 바꾸지 말고 `changes`의 `비고`에 적는다.
- 쓰이는 곳: 파워 길이↔케이스, GPU 전원 케이블 개수(`2× 8-pin` 요구를 충족하는지).

### B2. 케이스 40종 — 확장 사양
- 시트 `Case`. 채울 열: `최대 파워 길이(mm)` · `확장 슬롯 수` · `라디에이터 전면(mm)` · `라디에이터 상단(mm)` · `라디에이터 후면(mm)` · `색상` · 출처는 `확장 사양 출처 URL`.
- 행: 40행 전부(프랙탈 6, 리안리 5, JONSBO 4, 커세어 3, NZXT 3 …). 현재 파워 길이 1/40, 라디에이터 전면 2/40만 채워져 있다.
- 라디에이터는 **장착 가능한 크기(mm)를 세미콜론으로 나열**(예: `120;140;240;280;360`). 위치별로 다르면 열마다 적고, 동시 장착 제약은 `비고`에.
- `색상`은 제조사가 파는 **해당 SKU의 색**(예: `화이트`, `블랙`). 여러 색이 있는 모델은 시트의 상품 URL/이미지가 가리키는 색을 쓴다.
- 쓰이는 곳: 파워 길이·GPU 두께↔확장 슬롯·AIO 라디에이터↔케이스 검사, "흰색 케이스" 조건.

### B3. CPU 최대 소비전력(PL2/PPT) 남은 21종
- 시트 `CPU`. 채울 열: `최대 패키지 전력/PL2(PPT)(W)` · 출처는 `전력·계열 출처 URL`.
- 대상 21행: Intel Core Ultra 5 250K Plus · Intel Core Ultra 7 270K Plus · AMD Ryzen 5 7600X · 5 9600X · 5 7600 · 7 5800X · 7 5800X3D · 7 7700X · 7 7700X3D · 7 7800X3D · 7 9700X · 7 9800X3D · 7 9850X3D · 9 7900X3D · 9 7950X · 9 7950X3D · 9 9900X · 9 9900X3D · 9 9950X · 9 9950X3D · 9 9950X3D2
- **AMD 제품 페이지에는 PPT가 없다.** AMD 공식 자료(플랫폼 문서, 보도자료, 리뷰어 가이드, AMD Support의 소켓 AM4/AM5 사양 문서)에서 `PPT` 또는 `Package Power Tracking` 수치를 찾는다. AMD 공식 출처가 없으면 비우고 `제조사 미공개`. **TDP에서 계산하지 않는다.**
- Intel은 ARK의 `Maximum Turbo Power`를 쓴다(Plus 모델은 ARK에 없을 수 있음 → 제조사 발표 자료).

### B4. GPU 길이·높이 8종 (결정 D1 적용)
- 시트 `GPU`. 채울 열: `길이(mm)` · `높이(mm)` · `사양 기준` · 출처는 `물리 규격 출처 URL`.
- 대상 8행: RTX 5060 Ti · RTX 5060 · RTX 3050 (6GB) · RTX 3050 6GB · RTX 4060 · RX 7600 XT 16GB · RX 6650 XT · RX 6500 XT
- 규칙(D1): ASUS·MSI·GIGABYTE의 해당 칩셋 모델 중 **가장 긴 모델**의 길이·높이를 넣고, `사양 기준`에 `ASUS <모델명> 기준(3사 중 최장)`처럼 적는다. 3사 중 유통 모델이 없으면 있는 곳만 보고 `비고`에 적는다.
- `RTX 3050 (6GB)`와 `RTX 3050 6GB`는 같은 모델의 중복 행이다. 같은 값을 넣고 `비고`에 `중복 행`이라 적는다.

### B5. 메인보드 40종 — 슬롯·메모리·M.2
- 시트 `MainBoard`. 채울 열: `DIMM 슬롯 수` · `최대 메모리 용량(GB)` · `최대 메모리 속도(MT/s)` · `M.2 슬롯 수` · `M.2 PCIe 세대` · `SATA 포트 수` · 출처는 `확장 사양 출처 URL`.
- 행: 40행(ASUS 11, ASRock 10, GIGABYTE 10, MSI 9). 시트의 `CPU 지원 URL`이 이미 제조사 지원 페이지를 가리키니 같은 제품의 사양(Specifications) 탭에서 찾는다.
- `M.2 PCIe 세대`는 슬롯별로 세미콜론(`5;4;4`)으로 적는다. `최대 메모리 속도`는 **제조사가 명시한 최대 오버클록 속도**로, 기본(JEDEC) 속도와 다르면 `비고`에 둘 다 적는다.

### B6. 메인보드 최소 BIOS 버전 (B5와 별개)
- 시트 `MainBoard`. 채울 열: `CPU 세대별 최소 BIOS 버전`.
- 형식: `Ryzen 9000=2801;Ryzen 7000=1001`, `Core 14th=0812` (해당 보드가 지원하는 CPU 계열마다, **그 계열을 지원하기 시작한 BIOS 버전**). 값은 제조사 CPU 지원 목록에 적힌 그대로.
- ASUS(11종)는 CPU 지원 표가 동적 페이지라 1차에서 실패했다. **§2의 1~3번(렌더링 → PDF → Support 페이지)을 끝까지 시도한다.** 표가 CPU 모델별로 나뉘어 있으면 모델별 최소 BIOS 중 **계열에서 가장 높은 값**을 쓴다(그 계열의 모든 CPU를 지원하려면 필요한 버전).
- 40행 중 못 채운 것은 시도한 URL과 함께 사유를 적는다.

### B7. 성능 점수 (결정 D2 적용)
- 시트 `CPU`(40)·`GPU`(43). 채울 열: `성능 점수` · `성능 점수 출처 URL`. 점수 기준·측정일은 `비고`에 `PassMark CPU Mark 2026-09-xx`처럼 적는다.
- 한 시트는 **하나의 기준**으로만 채운다(CPU는 CPU Mark, GPU는 G3D Mark). 이름이 정확히 같은 항목만 가져오고, 없으면 비운다(비슷한 모델의 점수로 대신하지 않는다).
- Workstation GPU 11종(결정 D3)도 같은 방식으로 채우고 `비고`에 `워크스테이션`을 덧붙인다.

### B8. 가격 이상치 확인 (읽기 전용)
- 시트 값은 **고치지 않는다.** 판단만 `changes_B8.csv`로 준다.
- 대상: RX 6750 XT(2,950,000원) · RTX 4090(11,607,660원) · RTX 5090(8,977,480원) · RTX 6000 Ada(11,851,340원) · TeamGroup CX2(23,980원) + 각 종류(GPU·CPU·RAM·메인보드)의 **최고가 3종씩**.
- 각 제품을 **국내 판매처 2곳 이상**에서 확인한다. 열: `제품, 시트 가격, 판매처1 가격·URL, 판매처2 가격·URL, 확인 시각, 판단(정상/오류/판단 불가), 제안값`.
- 이 묶음은 가격을 수집하는 작업이 아니다. 판단에 필요한 최소한만 확인한다.

### B9. 게임 요구사양 CSV (엑셀과 무관)
- 산출: `game_requirements.csv` — 열: `게임, 별칭(쉼표), 권장 GPU, 권장 CPU, 권장 RAM(GB), 권장 VRAM(GB), 해상도·옵션 기준, 출처URL`.
- 기존 15종(발로란트, 리그 오브 레전드, 오버워치 2, 메이플스토리, 마인크래프트, 로스트아크, 배틀그라운드, 엘든 링, 디아블로 4, 콜 오브 듀티 워존, 발더스 게이트 3, 사이버펑크 2077, 검은 신화: 오공, 몬스터 헌터 와일즈, 스타필드)를 **공식 권장 사양으로 검증**하고, 국내 인기 게임을 **총 30~50종**으로 확대한다. 우리가 이 값을 성능 등급으로 옮긴다.
- 권장 사양은 게임 배급사 공식 페이지·스팀 상점의 시스템 요구사항을 쓴다. "권장(Recommended)" 항목만 쓰고 "최소"와 섞지 않는다.

- 대상: `data/pc_care_guides.json`(현재 18개, 형식 `{"id": "...", "text": "..."}`). 기존 항목은 수정하지 않고 **추가만** 한다.
- 새 검사와 짝이 되는 안내를 부품군별 2~4개: 파워 폼팩터·SFX 케이스, 16핀 GPU 어댑터, AIO 라디에이터 장착·간섭, RAM 슬롯 배치(듀얼 채널 A2/B2), M.2 슬롯 공유(SATA 비활성), GPU 처짐 방지, 케이스 팬·먼지 필터.
- 문장은 **사실과 확인 방법만**, 1~2문장, 한국어 존댓말. 판정어(안전합니다·위험합니다·적합·부적합)와 근거 없는 수치 금지. `id`는 `<부품군>_<주제>`(예: `psu_sfx_case`).

- 코드 변경(시드 스크립트, 마이그레이션, 로더, 규칙 파일, 테스트). 데이터가 채워지면 우리가 DB에 연결한다.
