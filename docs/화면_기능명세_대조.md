작성일: 2026-09-09 · 기준 커밋 `5f0ecbe` · 브랜치 `feat/recommend-engine`

> **세 문서가 서로 다르다.** 기능명세(`Plan Basket — 화면 흐름 및 기능 명세`),
> 초안 목업(디자인 캔버스 · 아트보드 11장 · 전부 PC), 백엔드 API 계약
> ([`추천엔진_API계약.md`](추천엔진_API계약.md))이 각각 다른 것을 말한다.

> 을 같이 봐야 한다. 이 문서가 그 대조표이고, 화면 담당자에게 넘기는 것이 이것이다.

## 0. 기준과 결정

**기능명세가 기준이다.** 9/8 17시 회의(`cmtsh6zpg008naikary8a9hle`)가 기획 담당에게
*"내일까지 기획서 완성"* 을 배정했으므로 명세가 초안 목업보다 뒤다.

이 문서를 쓰면서 정한 것 넷:

| 결정 | 값 |
|---|---|
| 산출물 형식 | 저장소 단일 HTML 목업 (`목업/planbasket.html`). 심사자가 보는 것은 공개 저장소다 |
| 카테고리 범위 | **셋 다 전 화면.** PC · 아기 용품 · 요리 식자재 각각 S2~S5-b |

| 데모 게임명 | **실제 게임명으로 바꾼다.** 팩의 `GAMES` 사전을 고친다 — 함정은 §5 |

## 2. 초안에 있고 명세에 없는 것 — 뺀다

- **A7 리뷰 작성 페이지** (작성해야 할 리뷰 · 개봉 확인 · 구매 인증 · 내가 쓴 리뷰)
- 제품 카드 **`대안 2개 보기`**
- 사이드바 대화 기록의 **금액 요약**(`부품 3개 · 1,482,000원`) — 명세 §7은 **상태만**
  표시하라고 한다(초안=표시 없음 / 확정=`가격 추적 중` / 도달=강조)

> A7 은 근거가 아주 없지는 않다. 같은 회의에서 사용자 리뷰 작성·공유가 구상됐다.
> 다만 **회의는 "제품 개별은 부담이 크니 추천받은 전체 구성(세트) 단위로"** 라고
> 정리했고 초안은 제품별이라 회의와도 어긋난다. 되살린다면 세트 단위이고,
> 그때는 명세에 먼저 들어가야 한다.

## 3. 정면 충돌 — 초안을 고친다

| 쟁점 | 명세 | 초안 |
|---|---|---|
| **주변기기** | *"본체만 취급한다. 관련 질문도 하지 않는다"* (§6.1) | `주변기기도 포함할까요?` 질문 · `케이스·쿨러·주변기기` 슬롯 그룹 · 실패 화면 문구 — **3곳** |
| **질문 세트** | 작업 / 조립 / 브랜드 / 케이스 크기 / 소음 / 확장 계획 — **6개** | 모니터 보유 / 해상도 / 주변기기 — **3개**, 명세에 없는 항목 |
| **`잘 모르겠어요`** | 모든 그룹에 포함 | 일부 그룹에만 |
| **입력 순서** | 카테고리 직후 **필수 입력값을 자유 대화보다 먼저** (§6.0) | 자유 입력이 먼저 |
| **리뷰 둘러보기** | 카테고리별 **클렌징 리뷰 탐색** | 내가 **쓸/쓴** 리뷰 (A7) |
| **용어** | 리뷰 클렌징 비율 / 클렌징 후 평점 / 검사 **Agent** ↔ 변호인 **Agent** | 조작 의심 % 제외 / 실사용 평점 / 검사 **AI** |

**용어는 명세 쪽이 바꾼 것이다** — 회의록 원문이 *"조작 의심 12% 제외"* 를 쓴다.
목업은 명세를 따르되, 백엔드 필드 정의(`excluded_high_risk` = 조작 확률 20% 이상
제외 건수)와 뜻이 어긋나지 않게 §4-1 의 단서를 함께 적는다.

## 4. 백엔드와의 접합 — 여기가 제일 중요하다

### 4-1. 명세가 요구하는데 API 에 필드가 없는 것

| 명세 | 백엔드 | 어떻게 할 것인가 |
|---|---|---|
| **평점 일체** — 원본 4.6 / 클렌징 후 4.2 / 평점 분포 / 항목별 평가 | `Evidence` 에 **평점 개념이 없다**. `samples`·`relevant`·`hits`·`excluded_high_risk` 뿐 | 목업은 예시값으로 그리고 **`백엔드 없음`** 배지를 단다. 필드 추가는 별건으로 판단 |
| 제품 이미지 · 수량 · 외부 구매 링크 | `set[]` = `category/code/name/price/added_by_claim/warning` | 같음 |
| 빈 슬롯 목록(`아직 선택되지 않음`) | 팩의 슬롯 정의가 API 로 안 나온다 | `GET /api/domains` 에 슬롯을 실어 주는 것이 싸다 |
| 리스트 저장 · 확정 · 목표가 · 가격 알림 · 로그인 | **전무** | 화면만. 가격 트래킹은 회의에서도 *"카테고리별 난이도가 다르다"* 에서 끝났다 |
| 필수 입력값 선수집 (§6.0) | 1차 호출이 `query` 를 받고 `needs_input[]` 을 돌려주는 구조 | 필수 입력을 `answers` 로 먼저 채워 1차를 부르는 형태로 맞출 수 있다 |

**`리뷰 클렌징 비율`은 만들 수 있다** — `excluded_high_risk / samples 합`. 다만
`unscored_risk > 0` 이면 *"20% 이상을 걸렀다"* 고 말하면 안 된다는 제약이 계약에
있다. 화면 문구가 이 값에 따라 갈려야 한다.

### 4-2. 백엔드가 주는데 명세 화면에 자리가 없는 것 — **이쪽이 더 아프다**

| 필드 | 무엇 | 왜 자리를 내야 하나 |
|---|---|---|
| `screening[]` | 하드 제약이 후보를 몇 개 걸렀나 | *"8GB였으면 뭐가 달라집니까"* 에 답하는 유일한 자리. **0을 0으로 보이는 것**까지가 약속이다 |
| `added_by_claim` | 반증 때문에 편성된 줄 | 안 보이면 검증이 설명용 장식으로 읽힌다 |
| `excerpt_policy: withheld` | **못 보여주는 것 ≠ 근거 없는 것** | 9/8 17시 원문 금지 결정에 대한 답. 이 서비스가 파는 구분이다 |
| `notices[]` · `budget_met` | 예산 초과 · 미채점 표본 고지 | `budget_met:false` 인데 합계만 보이면 예산을 지킨 줄 안다 |
| `indicators` | 조건 충족도 · 판정 분포 · 조작 확률 분포 | **종합 점수로 합치지 않는 것**이 설계다 |
| 합성 데이터 고지 | 리뷰가 합성이라는 사실 | 숨기지 않는 것이 합성을 고른 조건이었다 |

명세대로만 그리면 이 여섯이 화면에서 사라진다. 공정위 사용후기 규정(10/22 본격
적용) 대응이 Potential Impact 의 가장 강한 자산인데 **그 자산이 화면에 없게 된다.**

→ **목업은 이 여섯에 자리를 만든다.** 대부분 S4-a 추론 로그와 리스트 패널 상단
요약에 들어간다. 명세에 없는 것을 더하는 것이므로 §7 에 역제안으로 정리한다.

## 5. 실제 게임명 전환 — 완료 (2026-09-09)

**함정이 하나 있었다.** 팩의 `GAMES` 는 게임명 → 요구 VRAM 사전이고 그 값이
`screening[]` 깔때기를 움직인다. 목업의 *"VRAM 12GB 이상 — 후보 1개 제외"* 장면이
여기서 나오는데, 명세 §6.1 이 예로 든 **롤 · 오버워치는 요구 VRAM 이 낮다.**
공개된 권장 GPU 가 3~4GB 급이라 지금 카탈로그(전부 8GB 이상)에서는 **한 개도 못
거른다.** 저사양 게임만으로 데모를 짜면 3단계 ①이 통째로 안 보인다.

**발행처 문서에서 확인한 것만 넣었다.**

| 게임 | 요구 VRAM | 기준 | 출처 | 확인 |
|---|---|---|---|---|
| 인디아나 존스: 그레이트 서클 | **12GB** | QHD(1440p) 네이티브 권장 | Bethesda 공식 지원 문서 | 2026-09-09 |
| 몬스터 헌터 와일즈 | **8GB** | 1080p 60fps 중간 옵션(프레임 생성) 권장 | Steam 상점 페이지 · Capcom | 2026-09-09 |

가상 게임 둘(12GB · 8GB)을 실명 둘(12GB · 8GB)로 1:1 대체했으므로 **동작이 안
바뀐다.** 검사 22건 그대로 통과하고 *"깔때기가 제약별 효과를 낸다 (12GB −1 ·
8GB −0)"* 도 살아 있다.

**팀이 이름을 댄 롤 · 배틀그라운드 · 오버워치 2 는 아직 안 넣었다.**
9/7 17시(`cmtr1qwnh00bbzvkad7qsscp1`)에 *"롤/배틀그라운드/오버워치 등 특정 게임의
최소·권장 사양 기준으로 부품을 추천"* 이 논의됐지만, 발행처 페이지에서 수치를
확인하지 못했다(롤 지원 문서는 스크립트 렌더, PUBG Steam 페이지는 연령 확인 게이트).
확인되면 넣는다.

### 게임명은 실명, 제조사명은 가상 — 갈라 놓는 이유

팩이 가상 이름을 쓴 이유는 *"실제 제품에 대한 가짜 리뷰 판정을 만들지 않으려는
것"* 이다. **게임은 리뷰가 붙는 대상이 아니라** 발행처가 공개한 사실을 가리키는
이름이라 같은 위험이 없다. 합성 리뷰가 붙는 **제조사명은 가상으로 유지한다.**

### 곁가지로 드러난 것 — 목업이 거짓말을 하고 있었다

가상 게임에는 *"권장 사양이 2026-07-18에 한 차례 상향됐다"* 는 서사가 붙어 있었고,
그것이 2단계 "시차" 장면의 근거였다. 실명으로 바꾸면 **실제 게임에 붙은 거짓
주장**이 된다.

같은 장면을 사실로 다시 세웠다. Bethesda 문서의 최소(1080p · 8GB)와 권장(QHD ·
12GB)이 실제로 갈리므로 `VRAM 8GB → 12GB · FHD → QHD` 델타는 **그대로 참이다.**
바뀐 것은 축이다 — 시간축(상향됐다)이 아니라 등급축(최소와 권장이 다르다).

그리고 시차 자리에는 이렇게 적었다: **"발행처가 갱신 시점을 밝히지 않아 시차를 잴
수 없습니다."** 9/7 17시 지적에 대한 답으로는 이쪽이 낫다 — 모르는 것을 아는 척하는
것보다 못 잰다고 적는 쪽이 목업이 스스로 세운 규칙(*"모르는 것을 모른다고 말한다"*)
과도 맞는다.

### 같이 고친 것

`app/engine/packs/pc.py`(`GAMES` · `external_facts` · 모듈 docstring) ·
`tests/test_recommend_engine.py` · `README.md` · [`추천엔진_API계약.md`](추천엔진_API계약.md) ·
`app/engine/tools.py` · `목업/pc-부품.html` · `목업/README.md`.

`origin` 이 길어졌다 — 기준과 출처가 값과 함께 간다.

```
게임사 공개 권장 사양 · 〈인디아나 존스: 그레이트 서클〉 QHD(1440p) 네이티브 권장 · Bethesda 공식 지원 문서
```

**화면은 이 문자열을 잘라 쓰지 말 것.** 12GB 와 8GB 의 차이는 게임의 차이이기도
하지만 기준의 차이이기도 해서, 기준을 빼면 *"12GB 가 필요하다"* 를 설명할 수 없다.

## 6. 목업을 어떻게 만들 것인가

**한 파일에 카테고리 스위처 × 화면 목록.** 명세 §6.0 이 *"골격은 완전히 동일하고
5가지만 통째로 교체된다"* 고 했으므로, 그 주장을 **화면으로 증명하는 구조**를 쓴다.

```
목업/planbasket.html
  좌측  화면 목록  S1 · S2 · S3 · S4 · S4-a · S5 · S5-a · S5-b · S7 · 예외 · 모바일
  상단  카테고리   PC 본체 조립 / 아기 용품 / 요리 식자재   (S3~S5-b 에서 활성)
```

카테고리별로 갈리는 **5가지를 JS 정의 객체 하나**로 두고 화면을 거기서 그린다 —
필수 입력값 · 질문 세트 · 슬롯 구조 · 검증 규칙 · 리뷰 평가 축. 그러면 명세가
말한 *"정의 파일로 갈아끼운다"* 가 목업 코드 자체로 보인다.

기존 목업(`pc-부품.html`)의 관례를 따른다 — 단일 HTML, 라이트/다크 토큰,
키보드 좌우 이동, `목업 · 예시 데이터` 표시.

### 만드는 순서

명세 §12 가 *"랜딩 UI 이미지는 실제 화면 캡처로 대체 예정"* 이라고 적어 뒀으므로
**랜딩이 마지막이다.**

1. 공통 골격 — 3분할 · 사이드바 · 패널 폭 조절 · 카테고리 스위처
2. **PC 전 화면** S2 → S3 → S4 → S4-a → S5 → S5-a → S5-b (§4-2 여섯 자리 포함)
3. **아기 용품** — 시점 축 탭 · 리콜 경고 배지 · `이미 있어요` · 월령 타임라인
4. **요리 식자재** — 2단 요리 카드 · 중복 재료 배지 · `이 재료는 있어요` · 남는 양
