## 2. 테스트 실행 방법

기본 명령입니다. DB를 쓰는 테스트가 조용히 건너뛰어지지 않도록 `TRUEFIT_REQUIRE_TEST_DB=1`을 항상 붙입니다. (자세한 내용은 [AGENTS.md](../../AGENTS.md))

```bash
docker compose up -d db
PYTHONPATH=. UV_CACHE_DIR=/tmp/uv-cache TRUEFIT_REQUIRE_TEST_DB=1 uv run pytest -q -m "not llm_live"
```

- 테스트 시작 때 `truefit_test_<UUID>` 일회용 DB를 만들고, 마이그레이션과 시드를 적용한 뒤 끝나면 삭제합니다. 개발용 `truefit` DB에는 연결하지 않습니다.
- `llm_live` 마커 테스트는 실제 LLM API를 호출해 비용이 들기 때문에 **기본 실행에서 제외**됩니다.
- 시드 입력 파일(리뷰 번들 등)은 git에 없고 팀의 승인된 경로로 받아야 합니다.

| 목적 | 명령 |
|---|---|
| DB 없이 빠른 테스트 | `TRUEFIT_AUTO_TEST_DB=0 ... uv run pytest -q -m "not db and not integration"` |
| DB 테스트만 | `... uv run pytest -q -m db` |
| 통합 테스트만 | `... uv run pytest -q -m integration` |
| 실제 LLM 호출 테스트(비용 발생) | `MOCK_MODE=0 ... uv run pytest -q -m llm_live` |

## 3. 테스트 구성

| 구분 | 내용 |
|---|---|
| 단위·DB·통합 테스트 | pytest 약 220개 파일. 마이그레이션 체인, 제약·트리거, 소유권·접근 제어, 견적·확정 저장, 커뮤니티 API, 견적 점검 흐름 등 |
| 규칙·엔진 검증 | 호환성 무작위 조합, 추천 엔진 격자(60조합), 예산 배분 비교(`docs/validation/`) |
| 에이전트 평가 | LLM 에이전트의 성공률·적대적 입력·장애 주입(실제 모델) |
| 사양 추출 평가 | 견적 사진·텍스트에서 부품·가격을 읽는 정확도 |
| 검색 평가 | 가이드 검색, 리뷰 본문 검색, 실시간 부품 검색 |
| API·부하 점검 | Postman 흐름 점검(로컬·AWS), 동시 접속 단계 부하(AWS) |

설계 원칙: **추천·검증·가격 계산은 규칙 엔진이 하고, LLM은 해석과 설명만 맡습니다.** 그래서 정확성 검증의 대부분은 LLM 없이 결정적으로 반복할 수 있고, LLM이 필요한 부분만 실제 모델로 따로 평가합니다.

## 4. 평가 결과

### 4.1 자동 회귀 테스트

- 4,130개 통과, 실패 0, 오류 0(건너뜀 2, xfail 2, `llm_live` 26개 제외). 새 시드 번들과 새 테스트 DB에서 표준 명령으로 실행했습니다(2026-10-20).
- 마이그레이션 체인은 기준선 파일과 정확히 일치하고, 최종 스키마·제약·트리거·재실행(멱등)을 검증합니다.
- 소유권: 다른 사용자의 세션 조작 6종은 모두 403/404, 변조·깨진 토큰 4종은 401입니다.

### 4.2 추천 엔진과 호환성

| 항목 | 결과 |
|---|---|
| 호환성 판정 (무작위 600조합 × 7축) | 비호환 통과 0, 오탐 0 |
| 추천 엔진 격자 (60조합) | 가격·합계·호환성 100%, 예산 준수 46/60(76.7%) |

- 예산 미준수 14건은 최저가 구성도 예산을 넘는 경우이며, 이때 초과 금액과 줄이는 방법을 함께 안내합니다.

### 4.3 에이전트 (LLM)

실제 모델로 같은 입력을 20회 반복하고, 코드가 값·구조로 판정합니다(2026-10-20).

| 에이전트 | 케이스 | 결과 |
|---|---|---|
| 조건 대화 | 8케이스 × 20 | **160/160 (100%)** (10/12: 99.4%) |
| 결과 대화 | 6케이스 × 20 | **115/120 (95.8%)** (10/12: 92.5%) |
| 적대적 입력 | 유출·변조·평가어·날조·이미지 지시문 | 기준 위반 0 |
| 장애 주입 | LLM 예외·스키마 불일치·빈 응답 등 11가지 | 서비스 중단 없이 규칙 경로로 대체 |

- 견적 점검 대화는 요청·질문 문장 52건을 동작으로 올바르게 해석했습니다(52/52, 규칙 기반).

### 4.4 사양 추출 (견적 사진·텍스트)

| 정상 해상도 이미지 | 98.8~100% | 가격 정확, 합계·조립비 혼입 0 |
| 텍스트 6종 | 100% | |

- 흐림으로 판정된 사진은 **부품 이름은 읽되 가격은 쓰지 않고** 안내 문구를 표시합니다. 블러 2 이상에서 틀린 가격이 표시된 건수가 30건에서 0건으로 줄었습니다(같은 캡처의 단계별 블러 6회씩, 10/19).

## 5. 한계와 알려진 제약

- 일부 평가는 표본이 작습니다(케이스당 20회, 사진 수십 장). 작은 표본에서 오류가 없다는 것이 무오류를 뜻하지는 않습니다.
- 견적 점검 단계는 IP당 분당 호출 제한 때문에 AWS 부하 시험에서 제외했습니다.
- 자체 sLLM과의 비교는 하지 않았습니다. 관리형 API를 쓴 근거는 사진 인식 품질(10/01 모델 비교), 호출 비용, 운영 부담입니다.
