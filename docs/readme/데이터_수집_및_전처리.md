## 2. PC 부품 카탈로그

- **원본**: 다나와에서 수집한 부품 표(CPU·메인보드·RAM·GPU·SSD·PSU·케이스·쿨러 시트별 고정 컬럼). 8종 322행.
- **전처리** (`db/seed_pc_parts_specs.py`)
  - 시트마다 브랜드·모델·이미지는 공통 제품 테이블(`catalog.product`)에, 소켓·칩셋·TDP·크기 같은 스펙은 카테고리별 스펙 테이블(`catalog.cpu_spec` 등)에 **컬럼으로** 나눠 넣습니다.
  - 이름만 다르고 사양·가격이 같은 중복 행은 리뷰 데이터가 가리키는 이름 하나만 남깁니다(322행 → 319종).
  - 다나와 상품 코드가 확인된 252개 부품은 상품 페이지로 연결하고, 나머지는 "다나와에서 찾아보기"로만 안내합니다.
  - 가격은 판매처·관측 시점과 함께 저장(`catalog.offer`, `offer_observation`)해 언제 본 가격인지 남깁니다.
  - 원본 엑셀이 기준이며, 다시 실행해도 같은 행을 갱신할 뿐 중복이 생기지 않습니다.
- **쓰임**: 추천 엔진의 후보 수집 → 하드 필터 → 호환 검사 → 예산 최적화, 받은 견적서의 부품 이름 매칭.

## 3. 주변기기 카탈로그

- **원본**: 모니터 33종, 키보드 41종, 마우스 84종, 스피커 45종의 가공 CSV.
- **전처리** (`db/seed_peripherals.py`)
  - `-`·빈 칸·`미표기`·`해당없음`은 값을 추측하지 않고 비워(NULL) 둡니다. 포트 개수의 `없음`만 0으로, 래피드 트리거 `O/X`는 참/거짓으로 바꿉니다.
  - 원본 가격에는 판매처·관측일이 없어 **가격 스냅샷**(`catalog.peripheral_price_snapshot`)에만 보관하고, 구매 가능 가격으로 쓰지 않습니다.
  - 무게·크기·연결 방식·키압(최소·최대 g)·패널·주사율 등은 종류별 스펙 테이블에 넣습니다.
  - 추천할 때는 원문 스펙(예: "200–8,000 DPI (기본값 1,000 DPI)")을 판정용 값으로 바꿉니다. 괄호 안 주석과 별매 액세서리 조건 값은 버리고, 못 읽은 값은 "모름"으로 둡니다(`src/engine/peripheral_parse.py`).
- **쓰임**: 주변기기 후보 필터(무선·무게·크기 등), 모니터와 PC 그래픽카드의 HDMI·DP·USB-C 포트 호환 검사, 키압 선호 반영.

## 4. 제품 리뷰 → 리뷰 근거

리뷰는 원문을 그대로 쓰지 않고, **"어떤 제품의 어떤 관점이 좋았다/나빴다"** 라는 구조화된 근거로 바꿔 씁니다.

```text
원본 리뷰 14,825건
  │ ① 정리: 카탈로그 제품과 브랜드·모델 매칭, 중복·의심 리뷰 제외, 작성자 정보 마스킹
  ▼
리뷰 문서 5,653건 (evidence.review_document)
  │ ② 관점 규칙 102개 정의: 부품별로 무엇을 읽을지 (예: GPU 팬 소음, 마우스 트래킹·클릭)
  │ ③ LLM 추출: 리뷰마다 규칙에 해당하는 실제 사용 경험만 골라 방향(긍정/부정)과 원문 근거 문장을 기록
  ▼
관점 관측 3,676건 (evidence.review_aspect_observation)
  │ ④ 집계: 제품 × 관점별로 모아 표본 수를 고려해 점수화
  ▼
관점 집계 (evidence.review_aspect_aggregate) ──▶ 추천 점수의 후기 비중 · 추천 이유의 인용문
```

| 종류 | 원본 리뷰 | 리뷰 문서 |
|---|---:|---:|
| PC 부품 | 5,578 | 2,548 |
| 키보드 | 2,523 | 1,107 |
| 마우스 | 4,007 | 742 |
| 모니터 | 2,111 | 650 |
| 스피커 | 606 | 606 |
| 합계 | 14,825 | 5,653 |

- **③의 원칙**: 스펙 설명, 미래 가능성, 배송·포장 불만처럼 **실제로 써 본 경험이 아닌 문장은 근거로 쓰지 않습니다.** 근거가 없는 리뷰는 "근거 없음"으로 남기고 억지로 점수를 만들지 않습니다.
- **관점 규칙**: PC 부품 82개(GPU 16, 쿨러 15, CPU 11, SSD 11, 메인보드 9, 파워 9, 케이스 7, RAM 4), 주변기기 20개(종류별 5개).
- **임베딩**: 리뷰 본문은 임베딩해 pgvector에 저장합니다. 본문이 바뀌면 트리거가 기존 임베딩을 지우고, 배치 워커(`src/workers/review_embedding_batch.py`)가 다시 채웁니다.
- **별점**: 원본의 구매자 별점(1~5)도 `evidence.review_document.rating`에 함께 넣는다(0·없음은 NULL). 화면 표시 전용이며 추천 점수에는 쓰지 않는다. 자세한 동작은 [리뷰 평점 적재·표시](리뷰평점_적재_표시_계획_20261019.md).
- **적재**: ①~③의 결과는 리뷰 시드 번들(`data/review_seed/`)로 묶어 두고, `db/setup_all.py`가 번들을 읽어 ④까지 적재합니다. 번들의 `bundle_manifest.json`에 파일별 해시가 있어 파일이 바뀌었으면 적재를 멈춥니다.
- 원본 리뷰와 리뷰 시드는 리뷰 원문을 담고 있어 **Git에 올리지 않습니다**(README 10장 "처음 실행할 때"에서 따로 받습니다).

## 5. 커뮤니티 사용기 → 체감 근거

```text
사용기 글 (community.post, 제품 연결 포함)
  │ ① 분석 대기 등록: 글이 새로 올라오거나 고쳐지면 대기 목록에 추가
  │ ② LLM 추출: 제품 · 속성(그립감, 소음, 키감 등) · 방향 · 원문 문장 · 작성자 조건(손 크기, 용도)
  ▼
체감 근거 2,875개 (engine.peripheral_post_evidence)
  │ ③ 문장 임베딩 (text-embedding-3-small, 1536차원)
  ▼
주변기기 추천의 체감 점수 · "이런 사용자는 이렇게 느꼈어요" 인용
```

- 예시 사용기는 200편(이미지 111장)이며, 마우스·키보드·모니터·스피커·여러 제품·근거 아님(대조군) 묶음으로 나뉩니다. 자세한 적재 절차는 [커뮤니티 예시 사용기 적재 런북](../../data/community_examples/README.md)에 있습니다.
- 분석은 워커(`src/workers/peripheral_post_analysis.py`)가 바뀐 글만 골라 하므로, 글이 많아져도 비용은 새 글 수에만 비례합니다.
- 팀원마다 분석을 다시 돌리지 않도록, 분석이 끝난 결과를 스냅샷으로 내보내 같은 결과를 복원해 씁니다(README 10장 "처음 실행할 때").
