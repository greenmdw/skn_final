## 한 줄 요약

**1위 카드를 지금의 1,111px에서 600px 안팎으로 줄이고, 사용자가 말한 것의 근거를 위쪽에 먼저 보여 준다.** 나머지 근거는 "근거 전체 보기"로 접고, 다른 선택지는 누르면 위의 큰 카드가 그 제품으로 바뀐다.

## 진행을 두 단계로 나눈다

| 단계 | 내용 | 서버 필요 |
|---|---|---|
| **A** | 레이아웃·버튼·색·교체·이미지 대체·접기. 지금 응답으로 가능 | 없음 |
| **B** | 요청 항목 블록·스펙 한 줄·점수 축 라벨·대안 근거 | S1~S7 필요 |

A를 먼저 하고, B는 서버 필드가 오면 같은 자리에 연결한다. 필드가 없을 때의 모습은 각 항목에 적었다.

## F1. 1위 카드 구조

위에서 아래로, **이 순서로** 그린다(목업 "가장 잘 맞아요" 카드).

1. 이미지 · 이름 · 브랜드 · 가격
2. **스펙 한 줄**(칩 3~5개): `key_specs`(B). 없으면 줄을 그리지 않는다.
3. **요청 항목 블록**: 사용자가 말한 항목마다 한 박스(F7)
4. **이 제품이 뽑힌 이유**: 점수 축 상위 3개를 막대와 "N점 · 비중 N%"로(F8)
5. 줄 하나에 **"근거 전체 보기"(왼쪽, 텍스트 링크)**와 **"상품 페이지로 이동 ↗"(오른쪽 끝, 외곽선 버튼)**

규칙
- "상품 페이지로 이동"은 `product.product_url`로 새 탭을 연다. "근거 전체 보기"와 **떨어져서 별도 버튼으로 보여야 한다**(둘이 붙어 있으면 같은 종류로 읽힌다).
- 이미지 아래에 "담았습니다" 같은 버튼·배지를 **두지 않는다**. 1위는 이미 견적에 담긴 상태다.
- "근거 전체 보기"는 기본이 닫힘이다. 열면 같은 카드 안에서 아래로 펼쳐진다(페이지 이동 없음).
- 측정(1440px 폭, 근거 닫힘): 1위 카드 높이 **600px 이하**. 시나리오 3개를 목업과 같은 조건으로 재 보고 요청 문서 맨 아래 표에 적어 주세요.

## F2. 다른 선택지

- 가로 2열, **기본 펼침**(접지 않는다). 좁은 화면에서는 세로로 쌓는다.
- 카드 구성: 순위 라벨("추천 2위") · 이름 · 가격 · 지금 보는 제품과의 **가격 차이**(비쌈=빨강, 저렴=초록) · 스펙 칩 · **"다른 점"** · 요청 항목 요약 1박스 · 버튼 둘.
- 버튼
  - **"이 제품으로 바꾸기"**(주 버튼): 누르면 **위의 큰 카드가 그 제품으로 바뀌고**, 원래 1위는 다른 선택지 줄의 그 자리로 내려간다. 순위 라벨은 서버 순위 그대로 유지한다("추천 1위"). 큰 카드 라벨은 "직접 고른 제품 · 추천 2위".
  - **"상품 보기 ↗"**(외곽선): 그 제품의 `product_url`을 새 탭으로.
- 교체하면 견적에 담기는 제품도 바뀐다(`variant_id`, 기존 "다른 선택지 선택" 동작과 같은 경로). 합계 금액도 바로 바뀐다. 교체한 뒤 큰 카드 위치로 스크롤한다.
- "다른 점": 1위(지금 보는 제품)와 `key_specs`를 키로 비교해 **달라진 것만** 중립 글자로 쓴다. 예) `주사율 75Hz (지금 165Hz)`. 노랑·배경색을 쓰지 않는다. `key_specs`가 없으면 줄을 그리지 않는다.
- 교체한 제품의 근거는 `alternatives[].feel`(S1)로 그린다. 서버가 아직 안 주면 요청 항목·외부 리뷰만 보이고 사용기 타일은 그리지 않는다.

## F3. "근거 전체 보기" 패널

글을 나열하지 않고 **타일**로 그린다.

- 맨 위: 사용기가 0건이면 점선 박스로 "이 제품의 사용기가 아직 없어요 · 아래 외부 리뷰와 스펙을 기준으로 골랐어요" + "첫 사용기 남기기 →".
- **사용기 타일**(`feel.attributes[]` 한 항목당 한 타일): 항목 이름, 만족/불만 막대, "4/4명 만족" 같은 인원 문구(서버 `text`를 그대로), 인용 문장 1~2개(원문 보기 링크). **요청한 항목(`requested[].feel_codes`)의 타일을 맨 앞**에 둔다.
- 근거가 없는 항목은 타일을 만들지 않고 아래에 **한 줄로 모아** 접는다("근거 없음: 가성비 · 소음 · …").
- "아직 글이 적어 참고용이에요(항목당 1~4명)"은 타일마다 붙이지 말고 **섹션 제목 옆에 한 번**만 쓴다.
- **외부 리뷰**: 항목별 누적 막대(긍정=초록, 엇갈림=회색, 부정=빨강)와 "N건 중 긍정 N · 부정 N · 엇갈림 N". 대표 문장이 있으면(`contributions[].quote`, S7) 한 줄 인용.
- 인용 문장은 한글 원문만(기존 규칙). 영어 요약은 한글이 있을 때만.

## F4. 색 규칙 (토큰으로 고정)

| 색 | 의미 | 쓰는 곳 |
|---|---|---|
| 파랑 | 사용자가 요청한 것 | "요청하신 ○○" 라벨, 요청 타일, 주 버튼 |
| 초록 | 충족·긍정 | ✓ 태그, 긍정 막대, 저렴함 |
| 빨강 | 불만·부정 | 부정 막대, 비쌈 |
| 회색 | 보조 정보 | 스펙 칩, 건수, 안내 문구 |
| 노랑 | **주의가 필요할 때만** | "외부 리뷰 기준", "참고용" 표시 |

노랑을 "1위와 다른 점" 강조나 일반 카드 배경에 쓰지 않는다(경고처럼 읽힌다는 피드백).

## F5. 이미지 대체 표시

제품 이미지는 대부분 외부 쇼핑몰 주소라 실패할 수 있다. 주소가 없거나 `onError`면 **브랜드 이름 + "이미지 준비 중"**을 같은 크기 박스에 보인다. 깨진 아이콘이나 빈 칸을 남기지 않는다. 대안 카드의 작은 이미지도 같다.

## F6. 위쪽 정리

- **"이해한 내용"**은 기본 접힘(한 줄 요약 + 펼침). 칩과 × 제거는 지금과 같다.
- **"조건 바꾸기"**는 같은 줄 오른쪽에 둔다.
- 품목이 둘 이상이면 **탭**으로 나눈다(탭 이름 = 품목 이름, 선택 품목 합계는 위에 유지). 한 번에 한 품목만 그려 화면이 길어지지 않게 한다.
- 채팅 질문 칩("왜 이걸 1위로 골랐어?")이 결과 카드를 가리키는 연결은 이번 범위 밖이다.

## F7. 요청 항목 블록 (`requested`, B)

서버가 `requested[]`를 주면 항목마다 박스를 그린다. 라벨은 `요청하신 “{label}”`.

- `spec_checks`가 있으면 초록 ✓ 태그(`text` 그대로). `ok: false`는 빨강 ✗.
- `feel_codes`에 해당하는 사용기 속성의 인용을 **최대 2개**(`feel.attributes[].quotes`에서, 속성 순서대로) 따옴표로. 인용이 없으면 서버의 `text`(예: "4/4명 만족")만.
- 사용기가 없고 `external_aspects`에 해당하는 외부 리뷰가 있으면 노랑 작은 표시 "외부 리뷰 기준 · {항목} N건 중 긍정 N건" + 대표 문장 1개.
- **아무 근거도 없는 항목은 박스를 그리지 않는다**(빈 박스·"근거 없음" 문구 금지).
- `requested`가 `[]`이거나 없으면 블록 전체를 숨긴다.

서버 필드가 오기 전에는 이 블록을 그리지 않는다. 지금의 조건 태그(`✓`)는 그대로 둔다.

## F8. 스펙 한 줄·점수 축·"다른 점" (B)

- **스펙 한 줄**: `key_specs[]`를 순서대로 칩으로(`value` 그대로). 서버가 준 것만 보이고 값이 없으면 칩이 빠진다.
- **점수 축 3개**: `score_detail.axes`를 `points` 큰 순으로 3개, 이름은 서버 `label`(S6, 없으면 내부 이름을 그대로 쓰지 말고 그 축을 숨긴다), 막대 폭 = `value`, 문구 "N점 · 비중 N%".
- **가격 축**은 "N점"만으로는 뜻이 안 통한다. `price_position`(S6)이 있으면 "후보 {of}개 중 {rank}번째로 저렴"을 함께 쓴다.
- **다른 점**(F2): 위 `key_specs` 비교.

## F9. 건수 표기 통일

목업에서 "타건 소음 9건 중 긍정 7건"(엇갈림 제외)과 근거 막대 "10건 중 긍정 7 · 부정 2 · 엇갈림 1"이 한 화면에서 달라 보였다. **전체 건수 = 긍정 + 부정 + 엇갈림**으로 통일하고, 요약 태그도 "10건 중 긍정 7건"으로 쓴다.

덧붙여 한 것: 결과 카드에서 견적을 빼고 다시 담을 수 있게 품목 제목 줄에 "견적에서 빼기 / 견적에 다시 담기" 텍스트 버튼을 두었다(이미지 아래 버튼을 없앤 대신).

### 서버에 남긴 것 (peripheral)

- `key_specs` 에 원본 자리표시 값 `—` 가 그대로 나온다(예: 키보드 스위치 "기계식 · —"). 값이 `—`·`-` 이면 서버가 그 항목(또는 그 조각)을 빼야 한다.
- 외부 리뷰 대표 문장(`quote`)이 120자를 넘을 때가 있다(적당한 길이의 문장이 없으면 가장 긴 문장을 고른다). 없으면 **가장 짧은** 문장을 고르는 편이 낫다. 화면은 3줄로 잘라 보인다.
- 사용기 항목의 만족/불만 인원수를 숫자로 주지 않아 타일에 막대는 못 그렸다(서버 문구만 보인다). `good`·`bad` 건수를 주면 막대를 그릴 수 있다.
