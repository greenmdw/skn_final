SKN32 4팀 · 피드백 대응 분석

AI 적용 지점 매트릭스

“AI 쓸 수 있는 요소가 적어 보인다”는 피드백에 답하기 위해, 에이전트 능력 10종과 파운데이션 모델 능력 15종을 전부 나열하고 영업·구매·재고·승인 부서의 업무 33개와 맞대어 봤다. 24개 매칭을 네 축으로 점수화했고, 결론은 “하나만 새로 넣고, 이미 있는 셋을 화면에 꺼내라”다.

00

먼저 — 피드백을 어떻게 읽을 것인가

나열해놓고 보니 문제는 AI 지점이 적은 게 아니었다. 지금 시스템에서 모델이 실제로 일하는 곳은 이미 다섯 군데다 — 사양 태그 추출, 사양 유사도 판단, 협상 근거 문장, 리포트 요약, 어시스턴트의 tool 선택. 그런데 화면에 나오는 건 전부 숫자다. 가격이 내려가고 순위가 매겨진다. 숫자만 보면 규칙 엔진과 구별되지 않는다.

이 분석의 결론을 먼저 AI를 더 넣는 게 아니라, 룰 엔진이 절대 처리할 수 없는 입력을 받게 만들어야 한다. 음성·사진·제각각인 문서 양식이 들어오는 순간 “왜 AI인가”는 설명할 필요가 없어진다. 반대로 정형 필드만 들어오고 정형 숫자만 나오면, 안에서 무엇이 돌든 심사위원에게는 규칙 엔진으로 보인다.

그래서 아래 매칭에서 입력의 비정형성을 가시성 점수의 핵심으로 잡았다. 같은 값을 만들어내더라도, 손으로 채운 폼에서 출발하는 기능과 30초 음성 메모에서 출발하는 기능은 같은 화면이 아니다.

매칭 — 24개 후보와 점수

네 축으로 점수를 매겼다. 점수 = 고통 + 적합 + 가시성 − 비용이며, 비용만 낮을수록 좋다(1 = 하루, 5 = 2주 이상).

  1. 고통 — 그 업무가 지금 얼마나 아픈가
  2. 적합 — 규칙으로는 못 하고 모델이어야만 하는가 (낮으면 굳이 AI일 필요가 없다는 뜻)
  3. 가시성 — 5분 영상에서 “저건 AI다”가 즉시 보이는가
  4. 비용 — 9일 안에 얼마나 걸리는가

05

결론 — 하나 넣고, 셋을 꺼낸다

① 새로 넣는 것 — 딱 하나

O-01 · 미팅 직후 음성 메모 영업사원이 미팅을 마치고 나오며 30초 말한다. “오로라 데이터웍스 미팅했고, H100 다섯 대 9월 말까지 필요하다는데 NVLink는 필수고 예산은 대당 오천 이하로 맞춰달래.”

그러면 Amazon Transcribe가 받아쓰고, Bedrock이 여기서 거래처 · 품목 · 수량 · 납기 · 사양 · 예산을 뽑아 견적 초안과 활동 기록으로 만든다. 사람은 확인만 한다.

이 하나가 S-08(미팅 기록) · S-09(CRM 입력) · S-02(사양 정리) 세 업무를 동시에 친다. 셋 다 고통 4~5점인데 지금은 전부 손으로 한다.

왜 이것이어야 하는가. 음성은 규칙 엔진이 손댈 수 없는 입력이다. 폼에 숫자를 넣는 장면과, 말 한 마디로 견적 초안이 서는 장면은 심사위원에게 완전히 다르게 보인다. 게다가 Bedrock 외에 Transcribe라는 AWS 서비스를 하나 더 쓰게 되어 기술 점수에도 붙는다.

비용을 낮추는 방법. 라이브 마이크 녹음은 데모 당일 리스크가 크다. Phase A는 미리 녹음한 오디오 파일을 올리는 경로로 만든다 — 파일 → Transcribe → Bedrock → 필드 파이프라인은 전부 진짜로 돌고, 입력 방식만 고정이다. 라이브 마이크는 시간이 남으면 붙이는 스트레치.

② 이미 있는데 화면에 안 보이는 것 — 셋

후보지금 상태무엇을 바꾸면 보이나비용
O-02 자연어 → RFQ 구조화 rfq_parse.py에 이미 있고 POST /api/buyers/parse로 열려 있다. 그런데 데모 동선에 없다 음성 메모(O-01)의 뒷단으로 붙이면 그대로 재사용된다. 추가 개발 거의 없음 ●●●●●
O-16 사양 동일성 판단 spec_match.py가 LLM으로 태그를 뽑고 룰로 채점한다. 화면엔 spec 0.94 숫자 하나만 나온다 순위표에서 숫자를 눌렀을 때 “GDDR6 48GB ECC = HBM3 94GB 아님” 식으로 어떤 속성이 왜 맞고 틀렸는지 펼쳐준다. 데이터는 이미 spec_detail에 있다 ●●●●●
O-10 선택 근거 문장 순위표에 숫자만 있다. 왜 이 조합인지 설명이 없다 각 후보 아래 한 줄 근거를 모델이 쓴다 — “가격은 1위지만 납기 28일로 고객 기한을 3일 넘긴다”. 지금 프로토타입에서 사람이 2위를 고르는 장면이 이 문장 하나로 설명된다 ●●●●●

셋 다 새 기능이 아니라 표시 방식이다. 합쳐서 하루면 된다. 그런데 이걸 하면 화면에서 AI가 일하는 지점이 2곳에서 6곳으로 늘어난다.

③ Phase B에 이미 잡혀 있는 것 — 굳이 앞당기지 않는다

O-04(3자 대조) · O-09(자연어 이력 질의) · O-15(단가 이상) · O-18(마진 피드백)은 점수는 좋지만 이미 10/26 계획에 있고, 5분 영상에서는 협상 엔진의 변주로 보인다. 앞당기지 않는다. 다만 발표 슬라이드에 “AI 적용 지점 지도”로 한 장 넣어 구현분과 계획분을 색으로 구분하면, 지금 안 만들어도 범위는 보여줄 수 있다.

06

데모 컷 수정안

5분은 이미 꽉 차 있으므로 넣으려면 빼야 한다. 0:20–0:35의 문제 제기 자막 카드를 음성 메모 장면으로 교체하는 것을 제안한다 — 설명으로 때우던 15초가 실제 동작으로 바뀐다.

0:20–0:35
문제 제기 자막 — “The one question they can't answer: how many, by when?”
0:20–0:45
음성 메모 → 견적 초안. 영업사원이 미팅에서 나오며 30초 말한다 → 파형이 텍스트가 되고 → 거래처·품목·수량·납기·사양·예산 필드가 차례로 채워지며 CRM에 견적 초안이 선다.
“She just walked out of a meeting. She didn't open a form — she talked. Transcribe writes it down, the model pulls out the customer, the part, the quantity, the deadline, the spec. The quote drafts itself. She only checks it.”
0:45–1:15
캐릭터가 먼저 말을 검 — “5 requested, only 3 promisable” (기존 0:35 컷, 10초 뒤로)

이렇게 하면 영상 앞 45초에 비정형 입력 → 구조화 → 능동 감지가 연달아 나온다. “AI가 안 보인다”는 지적은 여기서 끝난다. 뒷부분(협상·감사·확정)은 그대로 두고 3:10–3:40 순위표 구간에서 15초를 줄여 총 길이를 맞춘다.

일정 영향 — 솔직하게 O-01은 9일 계획에 없던 작업이다. 오디오 파일 경로로 좁혀도 1~1.5일, 담당은 박회종(Odoo tool 세트와 파이프라인이 겹침)이 적합하다. 그만큼 어디선가 빼야 한다. 후보는 재고·ATP 뷰의 “기타 품목” 목록과 Bedrock AgentCore 스트레치다. 9/9 게이트에서 O-01이 안 붙으면 기존 0:20 자막 컷으로 되돌리는 것을 폴백으로 두고 시작한다.
