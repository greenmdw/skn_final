# 추천 엔진 수정 계획

작성일: 2026-10-12  
상태: 구현 전 수정 계획. 수정 전은 2026-10-12 확인한 현재 코드, 수정 후는 이 문서의 적용 목표다. 이 문서 작성으로 실행 코드나 설정이 변경되지는 않는다.

이 문서는 요구사항 해석, 후보 수집·구성, 사전 필터, 추천 점수 계산, 조합 탐색·검증, 최종 후보 선택, 결과 설명과 피드백까지 추천 엔진 전체의 수정 계획을 다룬다. 기존 추천 점수 수정 계획을 포함하며, 단계 사이의 입력·출력과 최종 선택 정책까지 범위를 넓힌다.

추천 점수는 사용자 조건에 따른 부품 후보의 추천 적합도다. 내부에서는 각 축과 추천 점수를 0~1로 계산하고, 사용자에게 표시할 때만 100을 곱한다. 성능 백분율이나 호환 성공 확률을 의미하지 않는다. 광고 제품에 대한 가산점은 추후 계획으로만 보관하고 이번에는 구현하지 않는다. 당장의 후보 평가·조합 선택에는 광고 여부를 반영하지 않으며, 원래 추천 점수·견적 평균 점수·조합 검증 점수에 광고 가산점을 포함하지 않는다.

## 1. 수정 목적과 전후 차이

현재는 가격이 부품별 참고 예산 이상이면 가격 점수가 모두 0이 되고, 밸런스 축은 목표 초과 성능에도 점수를 낮춘다. 호환여유 축은 실제 선택된 조합 대신 용도별 예상 전력과 최소 파워 용량을 기준으로 평가하고, 소음 축은 전력·쿨러 유형으로 실제 소음을 추정한다. 감점·가산점을 적용한 최종 점수에도 범위 제한이 없다. 밸런스 축을 제거하고 호환 여유는 조합 단계로 분리하며, 저소음 선호는 리뷰의 정숙성 평가로 반영한다. Pending·필수 정보 누락은 감점 대신 후보 보류·제외로 처리하고, RAM은 2개 구성을 추천 기준으로 하여 기존 가산점을 제거한다. 다른 개수의 구성 비교·선택은 추후 고도화로 보류한다. 최종 후보 선택은 원래 추천 점수와 기존 동점 처리 기준을 사용한다. 광고 가산점은 추후 계획으로 보류한다. 가격 차이와 내부 점수·표시 점수의 관계를 명확히 하기 위해 다음과 같이 수정한다.

| 항목 | 수정 전: 현재 구현 | 수정 후: 적용 목표 |
|---|---|---|
| 각 축의 점수 | 축마다 범위 처리 방식이 다름. 특히 밸런스는 음수 가능 | 모든 축의 계산 결과를 0~1로 제한 |
| 가격 축 | 참고 예산과 같거나 비싸면 모두 0점 | 참고 예산과 같으면 0.5점. 저렴해질수록 1, 비싸질수록 0에 수렴 |
| 밸런스 축 | 목표 등급과의 차이가 클수록 감점하며, 음수도 가능 | 부품별 추천 점수에서 제거. 성능 수준은 성능 축, 가격 부담은 가격 축에서 평가 |
| 호환여유 축 | CPU·GPU의 기준 전력 대비 부담과 파워의 최소 요구 대비 추가 용량을 평가. 정보가 없으면 0.5 | 부품별 추천 점수에서 제거. 실제 선택된 조합의 전력·냉각·크기 여유를 조합 단계의 별도 상세 평가로 다룸 |
| 소음 축 | CPU·GPU 전력과 쿨러 유형으로 추정. 저소음 요청에서 별도 가중치 적용 | 독립 축을 제거. 저소음 요청은 기존 리뷰 축 안의 팬·코일·펌프 정숙성 평가로 반영 |
| 가중치 | 현재 기본·우선순위별 설정의 합은 이미 1. 소음 민감 조건에서도 비율 조정으로 합계 유지 | 세 축 제거 후 가격·성능·리뷰 가중치를 소수점 두 자리 이내의 명시적 값으로 설정. 합계 1과 유효성 검증. 별도 소음 가중치 하한 조정 제거 |
| 기본 추천 점수 | 축별 계산 결과에 가중치를 곱해 합산. 가중합 자체에 범위 제한 없음 | 범위가 제한된 축을 가중합하고 결과도 0~1로 제한 |
| RAM 구성 기준 | 요구 용량과 일치하고 모듈이 2개 이상이면 별도 가산점 0.05 적용 | 동일 모듈 2개 구성을 기준으로 후보를 평가하고 RAM 가산점 제거. 다른 개수의 비교·선택은 추후 고도화로 보류 |
| 후보 적격성 | Pass 후보가 부족하면 Pending을 포함하고 감점. 남는 후보가 없으면 Fail까지 포함하는 완화 경로가 있음 | 필수 조건 Pending·필수 정보 누락 후보는 보류·제외. 후보가 부족해도 자동 승격하지 않고 데이터 보완·재탐색 후 부족 상태 안내 |
| 최종 추천 점수 | 가중합에 기존 감점·가산점을 적용하고 소수점 셋째 자리로 반올림. 최종 범위 제한 없음 | Pending·데이터 누락 감점과 RAM 가산점 제거. 적격 후보에 대해 `S_final = S_base`로 계산 |
| 사용자 표시 | 엔진의 `score`는 내부 값. 현재 새 견적 화면의 매핑은 예산 비중을 표시하며, 이를 추천 점수로 보면 안 됨 | 추천 점수를 표시할 때 `100 × 최종 내부 점수`로 변환하여 0~100점으로 표시 |
| 조합 검증 점수·판정 | 별도 검증 단계에서 `max(0, 100 − 쟁점 감점 합)`으로 계산하고 80점 이상이면 통과하므로, 위반 1건만 있으면 80점으로 통과 가능 | 호환 조건 위반이 1건이라도 확인되면 점수와 무관하게 해당 조합 탈락. 기존 점수 산식·감점·80점 기준은 유지하되 추천 적격성 확인을 별도로 적용. 필수 호환 정보 미확인은 보류. ‘확인 필요’ 판정 세분화는 추후 고도화 |
| 최종 후보 선택 | 예산 내 호환 조합에서 부품 추천 점수 합을 최대화. 동점이면 낮은 가격, 제품 키 순서로 결정 | 필수 조건·예산·호환 검증을 통과한 조합에서 원래 추천 점수 합을 최대화하고 기존 동점 처리 유지. 광고 가산점은 구현하지 않음 |
| 광고 우대 | 확인한 PC 순위·조합 탐색 경로에는 광고 가산점 정책이 없음 | 제8절에 추후 계획으로만 보관. 광고 가산점·전용 메타데이터·설정·저장·표시·탐색 변경은 이번 구현에서 제외 |

수정 후 적용 대상 축은 가격, 성능, 리뷰의 세 축이다. 사용하지 않는 축은 가중치를 0으로 설정한다. 가중치는 소수점 두 자리 이내로 정하고 합계가 1이 되도록 한다. 밸런스·호환여유·소음은 가중합과 축별 점수·기여도 표시에서 제외한다. 사용자의 저소음 우선순위와 소음 민감 입력은 유지하며 리뷰 계산에 사용한다.

### 1.1. 추천 엔진 전체의 단계별 범위

| 엔진 단계 | 이번 계획에서 다룰 내용 |
|---|---|
| 의도·요구사항 해석 | 용도·예산·우선순위·저소음 선호·필수 조건을 후속 단계에 일관되게 전달 |
| 후보 수집·구성 | 제품 식별자·판매 단위·가격·스펙·리뷰 출처를 유지. RAM은 2개 구성으로 통일. 광고 우대용 메타데이터 연결은 추후 계획 |
| 사전 필터 | 제5절의 필수 정보·조건을 확인하여 Pass만 평가 대상으로 전달. Pending·Fail의 자동 승격 제거 |
| 부품별 평가 | 적격 후보에 제2~4절의 세 축·가중치를 적용. Pending·데이터 누락 감점과 RAM 가산점을 제거하며 광고 가산점도 이 단계에 포함하지 않음 |
| 조합 탐색·검증 | 전체 예산·부품 간 호환성·RAM 2개 구성을 확인하고, 전력·냉각·크기 여유를 상세 평가. 호환 조건 위반 조합은 무조건 탈락, 필수 호환 정보 미확인 조합은 보류. 기존 검증 점수 체계 유지. ‘확인 필요’ 판정 세분화는 추후 고도화 |
| 최종 후보 선택 | 제8.1절에 따라 유효 조합의 원래 추천 점수 합·총가격·제품 키 순서로 선택하고 실제 선택된 조합을 다시 검증. 광고 우대는 추후 계획 |
| 설명·표시·저장 | 부품 추천 점수·견적 평균 점수·조합 검증 점수를 구분. 내부 추천 점수에만 100을 곱해 적합도로 표시. 광고 우대 전용 저장·표시는 추후 계획 |
| 피드백·재탐색·검증 | 사용자 조건이 바뀌면 필터부터 다시 평가. 기존 대비 추천 품질·조건 충족 여부를 비교하고 정책 버전을 기록 |

전체 단계가 계획의 검토 범위이며, 모든 단계의 기존 알고리즘을 일괄 교체한다는 뜻은 아니다. 이번에 확정한 변경은 각 절에 명시한다. 예산 배분 비율, 최소 성능 기준, 리뷰 내부 산식, 조합 검증의 기존 감점·통과 기준은 현행 정책을 유지하고 추후 검증·고도화 항목으로 관리한다. 주변기기 추천도 엔진 전체의 연결·회귀 확인 범위에 포함하지만, PC용 점수식과 광고 가산점을 별도 계산 경로에 자동 적용하지 않는다.

## 2. 각 축의 점수를 0~1로 제한

범위를 제한하는 공통 함수를 다음과 같이 정의한다.

```text
clip01(x) = min(1, max(0, x))

축 점수 s_i = clip01(축별 계산 결과 r_i)
0 ≤ s_i ≤ 1
```

예를 들어 계산 결과가 −0.5이면 0, 0.7이면 0.7, 1.2이면 1로 처리한다. 다만 유효한 입력에서 계산식 자체가 0~1을 보장하는 가격 축에는 별도의 `clip01()`을 적용하지 않는다. 모든 축은 높은 점수일수록 추천에 유리한 방향으로 계산한다.

현재 계산식과 수정 후 계산식을 비교하면 다음과 같다. `가격`과 `예산`은 부품 가격과 부품별 참고 예산, `등급`과 `목표`는 성능 등급과 목표 등급을 뜻한다. RAM의 가격은 제2.5절의 모듈 2개 구성 전체 가격을 사용한다.

| 축 | 수정 전 | 수정 후 |
|---|---|---|
| 가격 | `max(0, 1 − 가격 / max(예산, 1))`. 가격이 없거나 0이면 계산 시 1로 대체 | 입력 유효성 확인 후 `예산 / (예산 + 가격)`. 식 자체로 0~1 보장 |
| 성능 | `min(1, 등급 / 10)`. 상한만 제한 | `clip01(등급 / 10)`. 하한·상한 모두 제한 |
| 밸런스 | `1 − abs(등급 − 목표) / 4`. 목표가 없으면 0.5 | 축 자체를 제거. 계산·가중합·축별 설명에 포함하지 않음 |
| 리뷰 | 리뷰 서비스에서 이미 0~1을 검증. 저소음 요청에서 정숙성 항목의 상대 중요도를 높임 | 기존 계산·저소음 선호 반영·검증을 유지하고 최종 축 값에도 `clip01()` 적용 |
| 호환여유 | CPU·GPU는 `clip01(1 − 전력 / 기준 전력)`, 파워는 `clip01((용량 − 최소 요구 용량) / 최소 요구 용량)`. 정보가 없거나 다른 부품이면 0.5 | 부품별 축을 제거. 실제 조합의 여유를 제2.3절에 따라 별도로 평가 |
| 소음 | CPU·GPU는 전력을 역방향 정규화해 0~1로 제한. 쿨러는 유형별 고정값 사용 | 독립 축 제거. 리뷰의 정숙성 평가를 사용하며, 전력·쿨러 유형으로 별도 소음 점수를 계산하지 않음 |

성능 축은 현재 **제조사 라인업을 임시 성능 등급으로 변환한 점수**다. 벤치마크 실측값에 기반하지 않으며, 같은 등급 안의 세대·모델 차이와 등급 간 실제 성능 차이를 정확히 반영하지 못한다. 이번 수정에서는 임시 등급 기반 계산을 유지하되, 추후 용도별 벤치마크 데이터를 확보하고 검증한 뒤 **벤치마크 기반 성능 점수로 대체할 예정**이다. 대체 후에도 성능 축의 점수 범위는 0~1로 유지한다.

남은 성능·리뷰 축에서 기존에 중립값을 쓰는 조건은 제5절의 필수 정보 확인을 통과한 경우에만 유지한다. 최소 성능 판정에 필요한 CPU·GPU 성능 등급이 없으면 중립값으로 통과시키지 않고 Pending으로 보류한다. 반면 성능 등급을 사용하지 않는 RAM 등의 기존 중립값이나 선택적 리뷰 근거 부족에 대한 0.5는 정보 부족 표시와 함께 유지한다. 리뷰에 포함된 정숙성 점수는 사용 경험에 대한 평가이며, 실제 측정 소음이나 조용함의 보장을 의미하지 않는다.

입력값의 유효성 검사는 범위 제한 전에 수행한다. 가격과 참고 예산은 양수여야 하며, 가격을 임의의 1로 대체하는 기존 처리는 제거한다. 가격 누락·비정상 후보는 평가 대상으로 보내지 않고, 참고 예산이 누락·비정상이면 요구사항·예산 산정 오류로 처리한다. 숫자가 아닌 값·NaN·무한대도 계산 오류로 처리한다. 기존 중립값은 제5절에서 허용한 선택적 정보 부족에만 사용한다. 잘못된 입력이나 필수 정보 누락을 `clip01()` 또는 중립값만으로 정상 데이터처럼 처리하지 않는다.

여기서 범위 제한은 후보 목록의 최솟값·최댓값으로 점수를 다시 만드는 방식이 아니다. 0~1 범위 처리 외에 가격 축은 위 새 식으로 변경하고 밸런스·호환여유·소음 축은 제거하며, RAM은 제2.5절의 2개 구성 기준을 적용한다. 성능·리뷰 축의 기존 산식은 유지한다. 같은 제품과 같은 요구 조건의 점수가 후보 추가만으로 바뀌지 않게 한다. 모든 후보가 실제로 0점 또는 1점을 받을 필요도 없다.

### 2.1. 가격 축 계산식 변경

가격 축은 **부품별 참고 예산 대비 가격 부담**을 평가한다. 참고 예산은 `전체 구매 예산 × 해당 부품 배분 비율`로 정한 기준값이며, 개별 부품의 강제 구매 상한은 아니다. 전체 견적의 예산 준수 여부는 조합 탐색·검증 단계에서 별도로 검사한다.

```text
P = 부품 가격
B = 부품별 참고 예산

수정 전: s_price_old = max(0, 1 − P/B)
수정 후: s_price     = 1 / (1 + P/B)
                    = B / (B + P)

조건: P > 0, B > 0이며 둘 다 유한한 값
```

수정 전 식은 유효한 양수 가격·예산이 입력된 경우를 기준으로 표현했다. 수정 후 식은 `B > 0`, `P > 0`이면 분모 `B + P`가 분자 `B`보다 크므로 수학적으로 `0 < s_price < 1`을 만족한다. 따라서 가격 축에 별도의 `clip01()`은 필요하지 않다. 입력 유효성 검증은 유지한다.

- `P = B`이면 가격 점수는 0.5다.
- `P`가 0에 가까워질수록 가격 점수는 1에 수렴한다. 가격 0이나 누락값을 허용한다는 뜻은 아니다.
- `P`가 커질수록 가격 점수는 0에 수렴한다. 참고 예산 초과만으로 즉시 0이 되지 않는다.
- 같은 참고 예산에서 가격이 높아지면 점수가 계속 낮아져, 예산 이상의 후보도 가격 축에서 구분할 수 있다.

참고 예산이 20만 원인 경우의 전후 비교:

| 부품 가격 | 참고 예산 대비 | 수정 전 점수 | 수정 후 점수 |
|---|---:|---:|---:|
| 5만 원 | 0.25배 | 0.750 | 0.800 |
| 10만 원 | 0.5배 | 0.500 | 0.667 |
| 20만 원 | 1배 | 0.000 | 0.500 |
| 40만 원 | 2배 | 0.000 | 0.333 |
| 80만 원 | 4배 | 0.000 | 0.200 |

표의 소수점 셋째 자리 표시는 설명용이다. 실제 계산에서는 중간 반올림을 하지 않는다. 이 점수는 실제 시장 대비 저렴함이나 성능 대비 가성비를 직접 측정하는 값은 아니다. 참고 예산의 배분 비율에 대한 의존성도 남는다.

추후 가격 민감도를 조절하려면 `1 / (1 + (P/B)^α)`로 확장할 수 있다. 이번 계획의 초기값은 `α=1`로 고정하고, 다른 값은 시뮬레이션으로 검증한 뒤 별도 적용한다. 새 식은 기존 식보다 참고 예산 주변의 점수 변화가 완만하다. 세 축 제거 후 제3절의 가중치를 적용하고, 가격식 변경과 가중치 재배분이 최종 선택 가격·성능·예산 사용률·순위에 미치는 영향을 함께 확인한다.

### 2.2. 밸런스 축 제거

기존 밸런스 축은 실제 CPU·GPU 조합을 비교하지 않고, 개별 부품의 임시 성능 등급이 용도별 목표 등급에서 얼마나 떨어졌는지를 평가한다. 목표보다 낮은 성능은 성능 축에서 낮은 점수를 받고, 높은 성능에 수반되는 가격 부담은 가격 축에서 낮은 점수를 받으므로, 목표 초과 자체를 별도로 감점하지 않는다. 성능이 높으면서 가격도 합리적인 제품을 목표 초과만으로 불리하게 평가하지 않기 위해 밸런스 축을 제거한다.

성능·가격 점수는 가중합에 따른 선호 조정이므로 필수 조건을 보장하지 않는다. 최소 성능은 사전 필터에서, 전체 예산 준수 여부는 조합 탐색·검증에서 별도로 검사한다. 부품 간 균형 평가는 선택된 조합을 기준으로 다루며, 기존 판정은 유지한다. `ideal_tier`를 사용하는 기존 병목 힌트도 별도 기능으로 유지하며, 밸런스 점수 제거와 함께 일괄 삭제하지 않는다.

### 2.3. 호환여유 축 제거와 조합 단계의 여유 평가

기존 호환여유 축은 실제 조합의 상대 부품을 알기 전에 CPU·GPU의 전력과 파워 용량을 평가한다. 기준 전력 이상인 후보는 모두 0점이 되고, 전력 정보가 없으면 0.5점이 되어 정보 부족 후보가 오히려 유리할 수 있다. 파워는 이미 여유를 포함한 최소 요구 용량보다 더 큰 용량을 계속 우대한다. 이 값을 부품별 추천 점수에서 제거하고, 실제 선택된 조합을 기준으로 전력·냉각·크기 여유를 평가한다.

| 평가 항목 | 조합 단계에서 확인할 입력과 여유 |
|---|---|
| 전력 | 선택된 CPU의 최대 전력(없으면 TDP와 그 한계 표시), GPU 전력, 기타 구성품의 예상 부하와 파워 정격 용량을 함께 확인. 적용한 부하·안전 여유 기준과 남는 용량을 W 단위로 기록 |
| 냉각 | 선택된 CPU·쿨러·케이스의 조합과 전력 설정, 장착 조건 및 비교 가능한 냉각 시험 자료를 확인. 충분한 자료가 있으면 해당 조건의 온도·전력 여유를 기록하며, 서로 다른 제조사의 TDP 표기만으로 냉각 여유를 확정하지 않음 |
| 크기 | 케이스 허용 GPU 길이와 실제 GPU 길이, 허용 쿨러 높이와 실제 높이, 허용 파워 길이와 실제 길이의 차이를 mm 단위로 기록. GPU 두께·라디에이터 장착 위치 등 다른 부품과의 간섭도 확인 |

각 항목은 사용한 부품·입력값·단위·출처·평가 조건과 함께 결과를 기록한다. 필수 호환 조건의 충족 여부와 여유량을 구분하고, 여유가 크다는 이유로 다른 항목의 비호환을 상쇄하지 않는다. 정보가 부족하면 여유를 ‘확인 불가’로 표시하며, 임의의 0.5점이나 충분한 여유로 대체하지 않는다. 전력 여유 기준은 기존 요구 산정과 조합 검사의 안전 계수를 구분해 명시하고, 같은 여유를 중복 적용하지 않도록 검토한다.

이번 계획에서는 조합 여유를 부품 추천 점수에 다시 가산하지 않으며, 별도 종합 점수나 감점 값을 임의로 신설하지 않는다. 기존 호환 검사와 조합 검증 점수 산식·감점·통과 기준은 유지하면서 제5절의 필수 정보 확인을 추가한다. 필수 호환 조건을 확인할 수 없는 조합은 검증 점수가 통과 기준 이상이어도 최종 추천하지 않는다. 여유의 상세 평가는 별도로 추가하며, 비교 가능한 냉각 실측 자료처럼 정량적 여유 평가에만 필요한 선택적 정보의 부재를 곧바로 필수 호환 실패로 취급하지 않는다.

### 2.4. 소음 축 제거와 리뷰를 통한 저소음 선호 반영

전력·쿨러 유형만으로는 실제 제품별 소음 차이를 충분히 설명할 수 없으므로 독립 소음 축을 제거한다. 기존 `noise_proxy` 기반 계산, 쿨러 유형별 고정 점수, `noise_sensitive_min_weight`를 이용한 별도 소음 가중치 하한 조정을 사용하지 않는다. 전력이나 쿨러 유형 데이터 자체는 조합 검증 등에 필요하므로 유지한다.

사용자의 `priority=quiet` 또는 `noise_sensitive=true` 입력은 기존 리뷰 계산에 그대로 전달한다. 해당 부품의 리뷰 평가 항목에 팬 정숙성(`fan_quietness`), 코일 정숙성(`coil_quietness`), 펌프 정숙성(`pump_quietness`)이 있으면 저소음 선호에 따라 상대 중요도를 높인다. 현재 리뷰 정책의 일반 항목 원래 중요도 1, 정숙성 항목 원래 중요도 3을 유지하고, 선택된 전체 리뷰 항목의 합으로 나누어 정규화한다.

```text
리뷰 항목 중요도 a_j:
  저소음 요청이며 해당 항목이 정숙성 항목이면 3
  그 밖에는 1

리뷰 내부 가중치 alpha_j = a_j / Σ a_k
리뷰 축 점수 s_review = Σ alpha_j × q_j

q_j: 기존 리뷰 서비스가 계산한 0~1 항목 점수
```

3은 정규화 전 상대 중요도이며 정숙성 점수나 리뷰 최종 점수를 세 배로 곱한다는 뜻이 아니다. 두 저소음 조건이 모두 참이어도 중복으로 배율을 적용하지 않는다. 이 조정은 해당 부품에 정의된 리뷰 항목에만 적용하며, 정숙성 항목이 없는 부품에 소음 점수를 새로 만들어 넣지 않는다. 기존 사용 조건 선택·리뷰 점수 계산·중립값 정책을 유지하고, 리뷰 축의 바깥 가중치를 소음 가중치 하한으로 추가 조정하지 않는다.

정숙성 근거의 존재 여부, 선택된 사용 조건, 관측 수와 정보 부족 사유를 함께 표시한다. 근거가 없어 기존 리뷰 서비스가 중립값 0.5를 반환하더라도 ‘조용함 확인’으로 표현하지 않으며, CPU 전력이나 쿨러 유형으로 대체하지 않는다. 저소음 요청은 리뷰 정숙성 평가로 반영하고 별도의 소음 가산·감점은 추가하지 않는다.

추후 동일한 부하·측정 거리·환경에서 비교 가능한 소음 측정값을 확보하면 독립 소음 축의 재도입을 별도 검토한다. 이때 리뷰와의 중복 반영 및 정규화 기준을 검증하며, 이번 계획에는 재도입 수식이나 수치 기준을 확정하지 않는다.

### 2.5. RAM 2개 구성 기준과 고도화 범위

이번 적용에서는 **동일 규격·동일 용량의 RAM 모듈 2개 구성을 추천 점수 계산의 기준으로 확정**한다. 요구 총용량을 충족하는 2개 구성을 후보로 만들고, 그 구성 전체를 하나의 RAM 추천 후보로 평가한다. 예를 들어 필요한 총용량이 32GB이면 16GB 2개를 기준으로 한다. 2개라는 개수만으로 실제 듀얼 채널 동작이나 성능 향상을 보장한다고 표현하지 않는다.

| 단계 | 이번 적용 범위 |
|---|---|
| 후보 구성 | 요구 총용량을 충족하는 동일 모듈 2개 구성으로 비교 기준을 통일. 모듈당 용량·모듈 수·총용량·판매 단위를 구분하여 기록 |
| 가격 축 | 모듈 2개의 구성 전체 가격을 참고 예산과 비교. 낱개 판매 상품은 단가에 2를 곱하고, 2개 키트는 키트 가격을 그대로 사용하여 가격·용량을 중복 합산하지 않음 |
| 성능·리뷰 축 | 기존 임시 성능 등급·중립값과 리뷰 정책을 유지. 실측 근거 없이 듀얼 채널 성능 배율이나 2개 구성 가산점을 새로 만들지 않음 |
| 조합 단계 | 선택된 CPU·메인보드와의 메모리 규격, 슬롯 수, 최대 용량, 권장 슬롯 배치 및 해당 구성의 지원 속도를 확인. 확인할 자료가 부족하면 그 사유를 표시 |
| 검증 결과 반영 | 비호환인 2개 구성은 호환 가능한 다른 2개 구성으로 재선택. 해결 가능한 후보가 없거나 확인이 부족하면 해당 상태를 표시하며, 다른 개수로 자동 전환하지 않음 |

기존 `B_ram` 가산점은 제거한다. 후보를 2개 구성으로 통일하므로 ‘모듈 2개 이상이면 +0.05’라는 별도 보정을 둘 필요가 없다. 현재 RAM의 성능 정보가 부족해 중립값을 사용하더라도, 모듈 개수만으로 검증되지 않은 성능 점수를 추가하지 않는다. 이는 추천 구성의 초기 기준을 정하는 정책이며, 모든 사용자에게 2개 구성이 최적이라고 검증한 결과는 아니다.

**다른 모듈 개수를 고려하는 기능은 보류하고 추후 고도화로 둔다.** 1개·3개·4개 등 구성별 가격·용량·채널 동작·지원 속도·확장성 비교, 기존 RAM 재사용, 조합 단계에서 개수를 변경한 뒤 점수를 다시 계산하여 재선택하는 기능은 이번 적용에 포함하지 않는다. 향후에는 홀수 개수나 풀 뱅크를 일괄 가산·감점하지 않고 실제 조합을 기준으로 평가하는 방향을 검토한다. 기존 호환 검사와 사용자가 제공한 견적을 검토하는 기능을 이 추천 후보 기준만으로 제한하지 않는다.

## 3. 가중치 합을 1로 유지

밸런스·호환여유·소음을 제거하고 가격·성능·리뷰의 세 가중치를 설정한다. 기존 중요도 비율을 참고하되 분수나 긴 소수를 그대로 사용하지 않고, **소수점 두 자리 이내의 읽기 쉬운 초기값**으로 정한다. 기본값은 가격 0.45, 성능 0.30, 리뷰 0.25다.

아래 표의 값 자체를 설정·계산에 사용한다. 표시만 반올림하고 내부에서는 더 정밀한 가중치를 숨겨 사용하는 방식이 아니다. 이미 합계가 1인 표를 런타임에서 다시 정규화하거나, 이전 계획의 축 제거 비율을 중복 적용하지 않는다. 저소음 선호는 제2.4절에 따라 리뷰 내부에 반영하며, 별도 소음 축이나 소음 가중치 하한 조정은 적용하지 않는다.

최종 계산에 사용하는 가중치는 다음 조건을 만족해야 한다.

```text
0 ≤ w_i ≤ 1
Σ w_i = 1
각 w_i는 0.01 단위로 설정
```

음수·NaN·무한대 가중치와 합계가 1이 아닌 설정은 허용하지 않는다. 요청의 우선순위에 맞는 설정을 선택한 뒤 계산 직전에 유효성과 합계를 검증한다. 부동소수점 비교에는 작은 허용 오차를 사용할 수 있다. 이 자릿수 제한은 부품 추천 점수의 세 축 가중치에 적용하며, 리뷰 내부 가중치나 축 점수·중간 계산 결과를 두 자리로 반올림한다는 뜻은 아니다.

기본 가중치의 변경은 다음과 같다.

| 축 | 수정 전 | 수정 후 |
|---|---:|---:|
| 가격 | 0.35 | 0.45 |
| 성능 | 0.25 | 0.30 |
| 밸런스 | 0.15 | 제거 |
| 리뷰 | 0.20 | 0.25 |
| 호환여유 | 0.05 | 제거 |
| 소음 | 0.00 | 제거 |
| **합계** | **1.00** | **1.00** |

우선순위별 가중치도 같은 방식으로 단순화한다. `noise_sensitive=true`는 이 표의 바깥 가중치를 변경하지 않고 리뷰 내부의 정숙성 중요도에 반영한다.

| 설정 | 가격 | 성능 | 리뷰 |
|---|---:|---:|---:|
| 기본 | 0.45 | 0.30 | 0.25 |
| 성능 우선 | 0.20 | 0.60 | 0.20 |
| 가성비 우선 | 0.55 | 0.25 | 0.20 |
| 저소음 우선 | 0.40 | 0.25 | 0.35 |

성능 우선은 가격 영향이 지나치게 약해지는 것을 완화하기 위해 가격 0.20·성능 0.60·리뷰 0.20으로 설정한다. 가성비 우선은 가격을 가장 중요하게 평가하면서 성능 개선이 리뷰 개선보다 약하게 반영되지 않도록 가격 0.55·성능 0.25·리뷰 0.20으로 설정한다. 기본·저소음 우선 설정은 유지한다.

각 행의 합은 1이며, 모든 값은 소수점 두 자리 이내다. 이는 산식 검토를 반영한 휴리스틱 초기값이며, 최적값으로 검증되었다는 뜻은 아니다. 같은 점수 차이에 대한 상대 기여도를 조정한 것으로 실제 점수 분포에서의 영향까지 보장하지는 않는다. 특히 성능 축이 중립값으로 고정된 RAM 등은 별도로 확인한다. 추후 가중치를 조정할 때도 0.01 단위와 합계 1을 유지하고 추천 결과에 미치는 영향을 검증한다.

## 4. 기본 추천 점수 계산

수정 전에는 축별 원래 계산 결과를 그대로 합산한다.

```text
수정 전 기본 점수 = Σ w_i × r_i
```

수정 전 합산에는 밸런스·호환여유·소음 축이 포함된다(소음은 가중치가 양수일 때 계산). 수정 후에는 세 축을 제외한 가격·성능·리뷰를 0~1로 계산하고, 제3절의 가중치로 합산한 뒤 가중합에도 범위 제한을 적용한다. 아래 `w`는 수정 후 가중치를 뜻한다.

```text
S_base = clip01(Σ w_i × s_i)

       = clip01(
           w_price   × s_price
         + w_perf    × s_perf
         + w_review  × s_review
         )
```

모든 축이 0~1이고 가중치가 음수가 아니며 합계가 1이면, 가중합은 수학적으로 이미 0~1이다. 마지막 `clip01()`은 부동소수점 오차 등을 고려해 범위를 명시적으로 보장하는 처리다.

## 5. 필수 정보 확인과 후보 보류·제외

Pending·데이터 누락은 추천 적합도에서 빼는 점수로 처리하지 않는다. **필수 조건의 충족 여부와 필요한 정보의 존재를 먼저 확인하고, 통과한 후보만 추천 점수를 계산한다.** 높은 가격·성능·리뷰 점수로 미확인 상태를 상쇄하지 않는다. 제외는 해당 요청의 추천 대상에서 제외한다는 뜻이며, 카탈로그 데이터를 삭제하거나 미확인을 비호환으로 단정한다는 뜻이 아니다.

### 5.1. 수정 전후 산식과 처리 차이

수정 전에는 보정 후 값을 바로 반올림하여 후보 점수로 저장한다.

```text
S_old = round(Σ w_i × r_i − P_pending − P_gap + B_ram, 3)
```

수정 후에는 필수 정보·조건을 통과한 후보에만 다음 산식을 적용한다.

```text
부품 자체의 필수 정보·조건 확인 → Pass인 후보만 점수 계산

S_final = S_base
        = clip01(Σ w_i × s_i)

0 ≤ S_final ≤ 1
```

| 항목 | 수정 전 | 수정 후 |
|---|---|---|
| Pending 감점 `P_pending` | 판정 보류이면 0.20, 아니면 0 | 감점 제거. 필수 조건 미확인 후보는 추천 대상에서 보류하고 데이터 보완 후 재평가 |
| 데이터 누락 감점 `P_gap` | 감점 대상 스펙 누락 1개당 0.10, 최대 0.20 | 감점 제거. 필수 정보 누락은 후보 보류·제외, 선택적 정보 부족은 표시 |
| RAM 가산점 `B_ram` | 필요한 용량과 정확히 일치하고 모듈이 2개 이상이면 0.05, 아니면 0 | 제거. 제2.5절의 2개 구성 기준 사용 |
| 후보 부족 시 완화 | Pass가 부족하면 Pending을 포함. Pass·Pending이 모두 없으면 Fail까지 포함하는 경로가 있음 | Pending·Fail을 자동 승격하지 않음. 데이터 보완·재탐색 후에도 부족하면 그 상태 안내 |

`S_adjusted`와 세 보정값은 수정 후 산식에서 사용하지 않는다. `S_base`와 같은 값인 `S_final`, 축별 점수·가중치·기여분을 기록하고, 후보·조합의 적격 상태와 누락 사유는 점수와 별도로 기록한다. 보류·제외 후보에는 추천 점수 0점이나 낮은 점수를 부여하지 않고 ‘평가 보류’ 또는 ‘추천 제외’로 표시한다. 내부 계산과 순위 비교에서는 중간 반올림을 피하고 화면 표시 단계에서만 반올림한다.

### 5.2. 필수 정보와 선택적 정보의 구분

필수 정보는 **부품 종류·사용자 요구사항·실제 선택된 상대 부품**에 따라 명시적으로 정한다. 후보 중 누군가 그 스펙을 보유하는지에 따라 필수 여부를 바꾸지 않는다. 모든 후보에 해당 값이 없더라도 필수 조건이면 미확인으로 처리한다. 현재 `data_gap.specs` 목록을 그대로 전부 필수 항목으로 승격하지 않고, 실제 검사에 필요한지 분류한다.

| 구분 | 예시·판정 기준 | 처리 |
|---|---|---|
| 부품 평가·필수 요구 판정에 필요한 정보 | 유효한 구매 가격·판매 단위, 최소 성능을 요구한 CPU·GPU의 성능 등급, RAM 총용량·규격·2개 구성 여부 등 해당 요청에 적용되는 항목 | 스코어링 전에 확인. 누락은 Pending으로 보류·제외, 값이 확인되었고 조건에 미달하면 Fail로 제외 |
| 조합의 필수 호환 판정에 필요한 정보 | 선택된 CPU·메인보드의 소켓, RAM 규격·메인보드 슬롯·최대 용량, GPU·케이스 길이, 파워 용량·필요한 전원 커넥터 등 해당 조합에 적용되는 항목 | 개별 후보의 점수와 별개로 조합 단계에서 확인. 필요한 정보가 없으면 해당 조합의 최종 추천 보류 |
| 선택적 상세·평가 근거 | 사용자 필수 조건으로 지정되지 않은 리뷰·정숙성 관측, 정량적 냉각 여유 시험 자료, 해당 조합에서 사용하지 않는 인터페이스·커넥터 정보 등 | 누락만으로 제외하거나 감점하지 않음. 정보 부족·비적용을 구분하고 정의된 기존 중립값 정책만 유지 |

예를 들어 M.2 SSD를 선택하면 해당 슬롯 정보가 필요하지만, SATA 저장장치만 사용하는 조합에 M.2 슬롯 정보 누락을 이유로 제외를 적용하지 않는다. RAM의 성능 등급처럼 현재 해당 부품 평가에 정의되지 않은 항목도 누락으로 일괄 제외하지 않는다. 반면 최소 성능을 판정해야 하는 CPU·GPU의 등급을 기본값 0.5로 대체해 통과시키지 않는다. 지원 속도가 사용자 필수 조건이면 확인이 필요하고, 단순 상세 안내 항목이면 미확인 상태를 명시한다.

한 검사에 필수 세부 조건이 여러 개이면 각각의 정보와 충족 여부를 확인한다. 예를 들어 RAM 슬롯 수는 확인되었지만 메인보드의 최대 지원 용량이 없으면, 슬롯 수 검사만 통과했다는 이유로 전체 RAM 호환성을 확인 완료로 처리하지 않는다. 선택된 조합에서 필요 없는 검사는 비적용으로 구분하며, 미확인과 통과를 혼용하지 않는다.

리뷰 서비스가 근거 부족으로 반환하는 기존 중립값 0.5는 유지하되 실제 사용 평가가 확인되었다고 표현하지 않는다. 계산값의 NaN·무한대·범위 오류나 서비스 처리 오류는 단순 리뷰 근거 부족과 구분하고, 오류를 조용히 중립값으로 대체하지 않는다.

### 5.3. 후보 부족과 데이터 보완 흐름

1. 후보 수집 후 부품 자체의 필수 정보·조건을 검사하고, Pass·Pending·Fail 및 누락 키·사유를 구분해 기록한다. Pass만 점수 계산·순위·조합 탐색용 후보 풀에 전달한다.
2. Pending은 데이터 보완 대상으로 별도 보관한다. 기존 데이터 조회·수집·재탐색 범위에서 근거를 보완한 뒤 필터를 다시 실행하고, Pass로 확인된 경우에만 후보로 복귀시킨다.
3. Pass 후보가 적더라도 있는 후보만 사용한다. 조합 단계에서 추가로 필요한 필수 정보가 없으면 해당 조합을 보류하고 다른 유효 조합을 탐색하거나 정보를 보완한다.
4. 기존 재탐색 한도 내에서 해결되지 않으면 ‘추천 가능한 후보 부족’ 또는 ‘필수 정보 확인 필요’를 안내한다. 미확인·비호환·예산 초과 조합을 정상 추천 결과로 반환하지 않는다. 확인 요청용 진단 후보는 정상 추천과 구분한다.

최종 추천은 필수 조건을 충족하는 조합이어야 한다. 기존 조합 검증 점수 산식·감점·통과 기준은 유지하지만, 그 점수가 통과 기준 이상이라는 이유만으로 필수 호환 정보 미확인이나 확인된 비호환을 허용하지 않는다. 검증 점수는 쟁점 설명에 사용하고 최종 추천 적격 여부는 별도로 판단한다. 정보 보완이나 사용자 요구 변경 시 해당 필수 목록·필터·점수·조합을 다시 평가한다.

### 5.4. 호환 조건 위반 시 무조건 탈락과 확인 필요 처리 범위

이번 적용에서는 **해당 조합에 적용되는 호환 조건의 위반이 1건이라도 확인되면 해당 조합을 무조건 탈락**시킨다. 검증 점수·부품 추천 점수·전력이나 크기의 여유로 위반을 상쇄하지 않는다. 탈락 대상은 해당 조합이며, 부품 자체가 다른 상대 부품과도 항상 비호환이라는 뜻은 아니다. 다른 유효 조합은 계속 탐색할 수 있다.

| 상황 | 이번 적용 |
|---|---|
| 호환 조건 위반 확인 | 위반 건수와 점수에 관계없이 해당 조합 탈락. 예를 들어 위반 1건으로 기존 검증 점수가 80점이어도 최종 추천 불가 |
| 제5.2절에서 정한 필수 호환 정보 미확인 | 기존 계획대로 최종 추천 보류. 정보 보완·재탐색 후 다시 판정 |
| 그 밖의 ‘확인 필요’ | 기존 판정·건당 6점 감점·80점 기준을 잠정 유지. 이번에 중요도별 감점이나 새로운 판정 체계를 추가하지 않음 |
| 전체 예산·사용자 필수 조건 미충족 | 기존 계획대로 정상 추천에서 제외 |

‘확인 필요’를 정보 부족·추가 조치 필요·성능 제한 등으로 나누고, 사용자 요구·영향도·제조사 근거에 따라 처리하는 **판정 세분화는 추후 고도화로 보류**한다. 이 보류는 이미 정한 필수 정보 확인을 생략하거나 Pending을 자동 통과시키는 의미가 아니다. 확인된 위반, 정보 미확인, 해당 조합에 적용되지 않는 검사는 계속 구분한다.

조합 탐색 중의 비호환 제거와 완성 조합의 상세 검사는 유지한다. 최종 검증의 통과 여부와 재탐색 종료·결과 채택에는 위반 없음과 기존 필수 조건 확인을 함께 적용한다. 점수상 통과만으로 재탐색을 종료하거나, 탈락 조합을 높은 검증 점수의 결과로 다시 채택하지 않는다. 유효 조합을 찾지 못하면 후보 부족·확인 필요 상태를 안내한다.

## 6. 사용자에게 0~100점으로 표시

현재 엔진은 내부 `score`를 저장한다. 현재 새 견적 화면 매핑의 `score` 문자열은 `budget_share × 100`으로 만든 예산 비중이며, 추천 적합도 점수가 아니다. 수정 후에는 예산 비중과 추천 점수를 별도 항목으로 유지하고, 추천 점수를 표시할 때만 최종 내부 점수에 100을 곱한다. API·저장값 전체를 100점 단위로 바꾸거나 이미 변환한 값에 다시 100을 곱하지 않는다.

```text
사용자 표시 점수 D = 100 × S_final
0 ≤ D ≤ 100
```

화면에서는 소수점 한 자리로 반올림하는 것을 기본으로 제안한다. 이 문서의 표시 예시는 다음 자릿수가 5 이상이면 올리는 반올림(`round_half_up`)을 사용한다. 정수 표시가 필요하면 표시 단계에서만 정수로 반올림한다. 계산과 순위 비교에는 표시용으로 반올림한 값을 사용하지 않는다.

축별 상세 점수도 같은 방식으로 표시한다.

```text
축별 표시 점수       = 100 × s_i
축별 최종 기여 점수  = 100 × w_i × s_i
```

예를 들어 가격 축이 0.8이고 수정 후 기본 가중치가 0.45이면, 화면에는 **가격 점수 80점**, 기본 추천 점수에 대한 **기여분 36점**으로 구분해 표시할 수 있다. 수정 후에는 Pending·데이터 누락 감점이나 RAM 가산점을 표시하지 않는다. 보류·제외 후보는 점수 대신 적격 상태·누락 항목·사유를 표시한다.

## 7. 계산 예시

### 7.1. 수정 후 점수의 가중합과 사용자 표시

아래는 밸런스·호환여유·소음 축을 제거하고 수정 후 기본 가중치를 사용한 예시다. 가격은 참고 예산 20만 원, 부품 가격 5만 원으로 가정하여 `20 / (20 + 5) = 0.8`로 계산한다.

| 축 | 축 점수 | 가중치 | 가중치 적용 결과 |
|---|---:|---:|---:|
| 가격 | 0.80 | 0.45 | 0.360 |
| 성능 | 0.60 | 0.30 | 0.180 |
| 리뷰 | 0.50 | 0.25 | 0.125 |
| **합계** | — | **1.00** | **0.665** |

```text
필수 정보·조건을 통과한 후보:
S_final = S_base = 0.665
사용자 표시 = round_half_up(100 × 0.665, 1) = 66.5점

필터에서 필수 조건이 Pending이거나 필수 정보가 누락된 후보:
점수 계산·순위 비교 대상에서 제외
사용자 표시 = 평가 보류 또는 추천 제외 + 누락 사유
```

이 예시에서 밸런스·호환여유·소음 축은 계산에 포함하지 않는다. 가격식 변경뿐 아니라 세 축 제거와 가중치 재배분으로도 최종 점수와 순위가 달라질 수 있다.

### 7.2. 가격식 변경과 세 축 제거의 전후 차이

아래는 공식의 차이를 보여 주기 위한 계산 예시이며, 실제 제품 평가 결과는 아니다. 감점·가산점은 없다고 가정한다. 가격은 참고 예산 20만 원, 부품 가격 30만 원이며, 수정 전후에 각각 해당 기본 가중치를 사용한다.

| 축 | 수정 전 가중치 | 수정 후 가중치 | 수정 전 축 점수 | 수정 후 축 점수 |
|---|---:|---:|---:|---:|
| 가격: 참고 예산의 1.5배 | 0.35 | 0.45 | 0.00 | 0.40 |
| 성능 | 0.25 | 0.30 | 1.00 | 1.00 |
| 밸런스: 등급 10, 목표 3 | 0.15 | 제거 | −0.75 | 계산하지 않음 |
| 리뷰 | 0.20 | 0.25 | 0.50 | 0.50 |
| 호환여유 | 0.05 | 제거 | 0.20 | 계산하지 않음 |
| 소음 | 0.00 | 제거 | 0.50 | 계산하지 않음 |

```text
수정 전 가중합(반올림 전) = 0 + 0.25 − 0.1125 + 0.10 + 0.01 = 0.2475

수정 후 가중합 = 0.45×0.40 + 0.30×1.00 + 0.25×0.50
                = 0.180 + 0.300 + 0.125 = 0.605
수정 후 최종 내부 점수 = 0.605
수정 후 사용자 표시 = round_half_up(100 × 0.605, 1) = 60.5점
```

영향을 구분하기 위해 같은 입력으로 다음 네 경우를 비교한다. 세 축 제거 시에는 제3절의 단순화한 기본 가중치를 함께 적용한다. 아래 값은 최종 반올림 전 가중합의 비교다.

| 적용한 변경 | 가중합 |
|---|---:|
| 변경 없음 | 0.2475 |
| 가격식만 변경 | 0.3875 |
| 세 축 제거 + 가중치 단순화만 적용 | 0.425 |
| 가격식 변경 + 세 축 제거 + 가중치 단순화 | 0.605 |

이 예시는 기본 가중치를 사용하므로 기존 소음 가중치가 0이다. 소음 축 제거 자체의 영향과 가중치 단순화의 영향은 구분하며, 저소음 요청의 영향은 별도로 비교한다. 비교 시에는 같은 요청에 대한 기존 리뷰 정책을 유지해 소음 축 제거·가중치 변경과 리뷰 계산 변경의 효과를 혼동하지 않는다.

### 7.3. Pending·필수 정보 누락 후보의 처리 전후

보정 방식의 차이만 보기 위해 수정 전후의 가중합을 모두 0.85로 가정한다. 수정 전에는 Pass 부족으로 Pending 후보가 포함될 수 있고, 누락 스펙은 현재 감점 대상이라고 가정한 예시다.

| 후보 상태 | 수정 전 | 수정 후 |
|---|---|---|
| 필수 조건 Pending | `0.85 − 0.20 = 0.65`로 순위 경쟁 가능 | 평가 보류. 데이터 보완 후 Pass로 확인되어야 점수 계산 |
| 필수 정보 1개 누락 | `0.85 − 0.10 = 0.75`로 순위 경쟁 가능 | 추천 대상에서 보류·제외. 누락을 낮은 점수로 바꾸지 않음 |
| 필수 정보·조건 확인 완료 | 해당 감점이 없으면 0.85 | `S_final = S_base = 0.85`, 사용자 표시 85.0점 |

이 예시는 필수 확인이 점수 경쟁보다 우선함을 보여 준다. 선택적 리뷰 근거 부족처럼 중립값이 정의된 항목은 별도 정책을 유지하며, 필수 정보 누락으로 분류하지 않는다. 유효한 입력에서 수정 후 가중합은 이미 0~1이며, 범위 제한은 부동소수점 오차 등에 대한 처리로 유지한다.

## 8. 당장의 최종 후보 선택과 추후 광고 가산점 계획

**광고 제품에 대한 가산점은 추후 계획으로만 두고, 이번에는 구현하지 않는다.** 제8.1절만 당장의 최종 선택 기준이다. 제8.2~8.6절은 향후 검토할 설계안이며, 광고 메타데이터·가산점 계산·전용 설정·API·저장·화면·탐색 변경과 광고 정책 검증을 이번 완료 조건에 포함하지 않는다. 아래의 `beta=0.01`, `epsilon=0.01`도 향후 검토용 제안값이며 현재 적용값이 아니다.

### 8.1. 당장의 최종 조합 선택 기준

같은 요청·같은 구매 대상 슬롯으로 구성되고 필수 조건·전체 예산·호환 검증을 통과한 조합을 비교한다. 탐색 범위 안에서 부품의 원래 추천 점수 합이 가장 높은 조합을 선택하고, 동점이면 총가격이 낮은 조합, 제품 키 순서로 결정한다.

```text
S_i = S_final(i)
N = 비교하는 조합의 동일한 구매 대상 슬롯 수
Q(C) = (Σ S_i) / N
선택 순서: Q(C) 내림차순 → 총가격 오름차순 → 제품 키 순서
```

`N`이 같으므로 점수 합과 평균은 같은 순위를 만든다. 비교에는 반올림 전 내부 점수를 사용한다. 광고 여부는 후보 점수·후보 선정·최종 순위에 반영하지 않는다. 광고 가산점을 0으로 설정하는 기능을 새로 만드는 대신 관련 구현 자체를 보류한다. 기존 상위 후보 우선 탐색과 후보 부족 시 탐색 확대는 유지하며, 제5절의 위반 탈락·필수 미확인 보류를 최종 검증과 재탐색 결과 채택에도 적용한다. 제한된 탐색 결과를 전체 후보의 최고 적합도라고 표시하지 않는다.

### 8.2. 추후 원래 추천 점수와 선택용 점수 분리

광고 제품에는 **최종 후보 선택에만 사용하는 가산점**을 부여한다. 제5절의 `S_final`, 제6절의 사용자 표시 점수, 견적의 `avg_score`, 조합 검증 점수는 광고 여부와 관계없이 각 절의 산식대로 계산한다. 광고 가산점을 가격·성능·리뷰 축에 넣거나, 제거한 감점·가산점의 보정 항목으로 되살리지 않는다. 제5절에서 보류·제외한 후보는 광고 가산점의 적용 대상이 아니다.

```text
제품 i의 원래 추천 점수: S_i = S_final(i)
제품 i의 광고 가산점:    b_i = beta  (해당 요청에서 광고 적용 대상이면)
                            = 0     (그 밖에는)
제품 i의 선택용 점수:    T_i = S_i + b_i

초기 제안: beta = 0.01
```

`0.01`은 최종 선택에서 조금 우대하기 위한 휴리스틱 초기 제안이며 검증된 최적값은 아니다. 원래 추천 점수의 100점 표시 기준으로 1점에 해당하는 크기지만, 사용자 적합도에 1점을 더해서 보여주지는 않는다. `T_i`는 내부 선택용 값으로 최대 1.01이 될 수 있으며, 0~1 추천 점수나 사용자 표시 점수로 취급하지 않는다. 선택용 값에 `clip01()`을 적용해 상위 후보의 우대 차이를 없애지 않는다.

광고 대상은 제품 식별자와 광고 적용 기간·상태가 확인된 제품으로 정한다. 같은 제품에 여러 광고 계약이 있어도 가산점은 한 번만 적용한다. RAM 2개 구성도 하나의 추천 후보이므로 모듈 수나 낱개 구매 수량에 따라 가산점을 중복 적용하지 않는다. 광고 정보가 없거나 적용 기간이 지났으면 `b_i=0`으로 처리한다. 계약 금액에 비례해 가산점을 늘리는 정책은 이 추후 설계안에 포함하지 않는다.

### 8.3. 추후 유사한 적합도의 유효 조합에서만 우대

PC의 최종 결과는 부품 조합이므로 개별 광고 제품을 먼저 확정한 뒤 나머지 부품을 끼워 맞추지 않는다. 같은 요청·같은 구매 대상 슬롯으로 구성된 조합 전체를 비교한다.

```text
N: 비교하는 조합의 구매 대상 슬롯 수. 비교 중에는 동일하게 유지
Q(C) = (Σ S_i) / N             # 조합 C의 원래 평균 추천 점수
B(C) = (Σ b_i) / N             # 조합 C의 광고 가산점 평균
R(C) = Q(C) + B(C)             # 조합 C의 최종 선택용 점수

0 <= B(C) <= beta

F: 사용자 필수 조건·전체 예산·부품 간 호환 조건을 충족한 조합 집합
Q_best = max(Q(C), C in F)
E = {C in F | Q(C) >= Q_best - epsilon}

초기 제안: epsilon = 0.01
최종 선택: E 안에서 R(C)가 가장 높은 조합
```

`beta`는 광고 우대의 크기이고, `epsilon`은 광고 적용 전 최고 적합도에서 허용할 차이다. 둘은 목적이 다른 설정으로 분리한다. 초기 적용 범위는 각각 유한한 `0~0.01`로 제한하고, 음수·NaN·무한대·상한 초과 설정은 허용하지 않는다. 여러 슬롯에 광고 제품이 있어도 평균을 사용하므로 조합의 광고 가산점이 `beta`를 넘지 않는다. 광고 제품 수가 늘어도 조합 가산점의 최대치는 `beta`다. 기존 탐색이 사용하는 점수 합과 이 절의 평균 점수를 혼용하지 않으며, 합으로 구현할 경우 가산점과 허용 차이도 동일한 `N` 배율로 변환한다.

최고 적합도와의 차이가 0.01 이내라는 것은 평균 추천 점수 차이를 제한한다는 뜻이며, 실제 성능 차이가 1% 이내이거나 모든 부품의 특성이 같다는 보장은 아니다. 가격·성능·리뷰의 차이는 별도로 확인하고 제8.6절의 추후 비교 검증에 포함한다.

필수 조건이 확인되지 않은 Pending 후보, 필수 정보 누락 후보, 예산 초과·비호환·검증 실패 조합은 제5절에 따라 광고 여부와 무관하게 최종 추천 대상에서 제외한다. `F`가 비어 있으면 데이터 보완·재탐색 후 후보 부족 또는 확인 필요를 안내하고, 광고 가산점으로 조건 미충족을 상쇄하지 않는다. 사용자가 특정 제품을 지정·제외했거나 유지할 부품을 정한 경우에도 필수 조건 확인을 생략하지 않는다. 광고 가산점은 조합 검증의 감점을 상쇄하거나 통과 기준을 바꾸지 않는다.

선택용 점수가 같으면 원래 평균 추천 점수가 높은 조합, 총가격이 낮은 조합, 제품 키 순서로 결정한다. 광고가 없거나 기능을 끈 경우에는 `B(C)=0`이므로 광고를 제외한 선택 결과와 같아야 한다.

### 8.4. 추후 광고 적용 시 계산 예시

동일한 8개 구매 대상 슬롯의 유효 조합을 비교하고 `beta=0.01`, `epsilon=0.01`이라고 가정한다. 아래 표의 원래 평균 적합도는 사용자 표시 기준의 값이며, 실제 비교는 반올림하지 않은 내부 값으로 수행한다.

| 조합 | 원래 평균 적합도 | 광고 대상 슬롯 | 광고 가산점 평균 | 선택용 값(100배 환산) | 처리 |
|---|---:|---:|---:|---:|---|
| A | 80.0점 | 0/8 | 0 | 80.0 | 비교 대상 |
| B | 79.8점 | 4/8 | 0.005 | 80.3 | 허용 차이 이내이며 선택용 값이 가장 높아 최종 선택 |
| C | 78.5점 | 8/8 | 0.010 | 79.5 | 최고 적합도와 1점 넘게 차이 나므로 비교 대상에서 제외 |

B를 선택해도 사용자에게 표시하는 평균 적합도는 **79.8점**이다. 80.3은 선택 정책의 계산을 설명하는 내부 값이며 추천 적합도 점수로 표시하지 않는다. ‘광고’ 표시와 함께 유사한 적합도의 후보 중 광고 가산점이 최종 선택에 반영되었음을 안내한다. 광고가 있다는 사실과 광고 우대로 선택 결과가 바뀌었다는 사실은 구분해 기록한다. 이 예시는 향후 광고 정책을 구현했을 때의 동작이다. 당장의 선택 기준에서는 같은 유효 조합 중 원래 평균 적합도가 가장 높은 A를 선택한다.

### 8.5. 추후 탐색·검증·저장에 반영할 내용

현재 탐색은 원래 점수 상위 후보를 먼저 자르고, 그 안에서 예산 내 호환 조합을 찾으면 종료한다. 최종 선택 단계에서 광고 가산점만 더하면 유사한 광고 후보가 이미 잘렸거나, 원래 점수 기준 가지치기로 제외되어 정책이 작동하지 않을 수 있다. 다음과 같이 탐색과 연결한다.

1. 필수 조건을 통과한 원래 후보 풀을 보존하고, 광고 여부와 무관한 동일 탐색 범위에서 기준 조합과 `Q_best`를 구한다.
2. 같은 후보 풀에서 `Q(C) >= Q_best - epsilon`인 유효 조합을 비교해 `R(C)`를 최대화한다. 단순 상위 N개 목록만으로 확정하지 않으며, 가지치기에서도 원래 점수 하한과 남은 광고 가산점의 상한을 함께 고려한다.
3. 원래 점수·광고 가산점·선택용 점수와 정책 버전을 별도 필드로 전달하고, 최종 선택된 조합에 필수 정보 확인과 기존 조합 검증을 다시 수행한다. 실패·필수 정보 미확인이면 해당 조합을 제외하고 제5절에 따라 재탐색·데이터 보완한다.
4. 탐색 완결성만 확인할 수 없다면 광고 우대를 중단하고 필수 조건이 확인된 무광고 기준 결과와 탐색 제한 사유를 제공한다. 예산·필수 호환성 자체를 확인할 수 없으면 기준 결과도 정상 추천으로 반환하지 않는다. 제한된 탐색 결과를 전체 후보의 최고 적합도라고 표시하지 않는다.

저장·설명에는 원래 제품 점수와 조합 평균, 제품별 광고 적용 여부·가산점, 조합의 가산점 평균·선택용 값, `beta`·`epsilon`, 광고를 제외한 기준 조합과의 적합도·가격 차이, 탐색 범위·완료 여부, 정책 버전·판정 시점을 포함한다. 새 필드의 실제 API·저장 구조는 구현 시 기존 스키마와 함께 확정한다. 광고 여부는 제품 가까이에 명확히 표시하고, 광고 우대로 선택되었다면 그 사유도 함께 안내한다.

### 8.6. 추후 광고 정책의 확인 기준과 검증

다음 항목은 광고 우대 구현을 재개할 때 확인하며, 당장의 구현·완료 기준에서는 제외한다.

- 광고 여부를 변경해도 동일 제품의 원래 추천 점수·축별 기여도·리뷰 점수와 동일 조합의 `avg_score`·검증 점수는 변하지 않는가.
- 광고 선택용 가산점이 제품당 한 번만 적용되고, 같은 제품의 중복 계약·RAM 모듈 수·구매 수량에 따라 증가하지 않는가.
- 조합 가산점 평균이 `beta` 이하이고, 원래 최고 평균 적합도와 `epsilon` 넘게 차이 나는 조합을 광고로 선택하지 않는가.
- `beta`·`epsilon`이 유한한 `0~0.01`인지 검증하고, 비정상 설정을 범위 제한만으로 정상 처리하지 않는가.
- 광고 대상이 최고 적합도와 정확히 `epsilon`만큼 차이 나는 경계에서도 반올림 전 값으로 일관되게 판단하는가.
- 광고 대상이라도 필수 조건 미확인·예산 초과·비호환·검증 실패 후보가 광고 우대를 받지 않는가.
- 원래 상위 N개에서 제외된 유사 광고 후보도 동일 후보 풀의 최종 선택 탐색에서 평가되며, 탐색 제한 시 광고 우대를 중단하는가.
- 광고가 없거나 기능이 꺼졌으면 원래 선택 결과와 같고, 선택용 점수가 같은 경우 원래 적합도·가격·제품 키 순서로 결정되는가.
- 광고 적용 기간 만료·정보 누락·재탐색 시 이전 광고 가산점이 남거나 누적되지 않는가.
- 광고 선택용 값이 적합도 표시나 견적 평균에 섞이지 않고, 광고 여부·선택 우대 사유와 정책 버전이 설명·기록되는가.

광고를 끈 결과와 켠 결과를 같은 요청·가격·리뷰·광고 정보 스냅샷 및 같은 후보 풀에서 비교한다. 원래 적합도 차이, 총가격 차이, 선택 변경률, 광고 제품 선택 비율, 필수 조건 위반 여부, 탐색 소요 시간을 함께 확인한다. 무광고·동점·허용 차이 경계·다수 광고·기간 만료·Pending·후보 없음·탐색 제한·재탐색을 고정 시나리오에 포함한다. `beta`와 `epsilon`은 먼저 `0`, `0.005`, `0.01` 등에서 민감도를 비교하고, 사용자 적합도와 광고 우대 효과를 확인한 뒤 적용값을 확정한다. 이 선택 정책 설정은 제3절의 세 축 가중치 자릿수 제한과 별개다.

## 9. 적용 범위와 확인 기준

문서의 범위는 제1.1절의 추천 엔진 전체 단계다. 제2~7절의 계산식은 PC의 같은 부품 종류 안에서 후보를 비교하는 추천 점수에 적용하고, 제8.1절의 기준으로 최종 조합을 선택한다. 제8.2~8.6절의 광고 가산점은 추후 계획으로만 보관하며 이번 구현·완료 기준에서 제외한다. 주변기기 추천은 별도 계산 경로이므로 기존 동작을 회귀 확인하고, 점수식·광고 정책의 적용은 별도 설계 후 확장한다. 견적의 `avg_score`는 선택한 부품의 `S_final` 평균을 내부 값으로 사용하고 화면에는 100을 곱해 표시한다. 이는 광고 가산점을 포함하지 않는 부품 추천 점수의 평균이며 별도의 조합 검증 점수와는 구분한다.

| 적용 위치 | 수정할 내용 |
|---|---|
| 필수 정보·사전 필터 | 부품 종류·요구사항·실제 조합에 따른 필수 목록과 적용 조건 명시. Pending·Fail 자동 승격 제거. 부품 평가에 필요한 정보가 확인된 Pass만 점수 계산에 전달 |
| 부품별 점수 계산 | 밸런스·호환여유·소음 축 제거, 가격 축을 `B / (B + P)`로 변경하고 공통 범위 제한·입력값 검증 적용. Pending·누락 감점과 RAM 가산점 제거 후 `S_final = S_base` |
| RAM 추천 후보 | 동일 모듈 2개 구성 기준으로 총용량·구성 전체 가격을 평가. 기존 RAM 가산점 제거. 다른 개수의 비교·선택은 추후 고도화 |
| 광고 가산점 관련 기능 | 추후 계획. 광고 메타데이터·가산점·설정·전용 API·저장·화면·탐색 변경을 이번에는 구현하지 않음 |
| 가중치 결정 | 세 축 제거 후 제3절의 소수점 두 자리 이내 가중치를 직접 적용. 소음 가중치 하한 조정 제거, 자릿수·유효성·합계 검증 |
| 저소음 선호 | 기존 리뷰의 정숙성 중요도 조정·사용 조건 선택·근거 부족 표시 유지. 별도 소음 점수·가산·감점 없이 반영 |
| 규칙·설정 | 소음 대용값과 `noise_proxy`·`noise_sensitive_min_weight`, RAM 가산점과 `ram_dual_channel_bonus` 제거. `PENDING_SCORE_PENALTY`·`data_gap` 기반 감점 제거. 기존 누락 스펙 목록을 재분류해 필수 정보·조건별 검사 설정으로 관리. 광고 정책 설정 추가는 추후 계획 |
| 점수 저장·순위 비교 | 내부 0~1 값 유지, 표시용 반올림 값과 구분. 계산 방식 버전을 구분해 기존 점수와 혼용 방지 |
| 최종 조합 선택 | 필수 조건·전체 예산·호환 검증을 통과한 조합에서 원래 추천 점수 합이 높은 순으로 선택. 동점이면 총가격이 낮은 순, 제품 키 순. 광고 가산점·선택용 점수는 구현하지 않음 |
| 견적 평균 점수 | 제한된 부품 점수를 평균하고 중간 반올림을 피함 |
| 사용자 화면 | 적격 후보의 내부 추천 점수에 100을 곱해 표시. 보류·제외는 점수 0점 대신 상태·필수 누락 사유 표시. 축별 점수·기여도 설명에서 밸런스·호환여유·소음과 제거한 점수 보정 삭제. 저소음 요청의 리뷰 정숙성 근거 표시 |
| 조합 검증 | 기존 검증 점수 산식·감점·80점 기준 유지. 호환 조건 위반이 1건이라도 있으면 점수와 무관하게 해당 조합 탈락. 필수 호환 정보 미확인은 보류. 최종 통과·재탐색 종료·결과 채택에 동일 조건 적용. 전력·냉각·크기 여유와 RAM 2개 구성 확인 추가. ‘확인 필요’ 판정 세분화와 다른 RAM 개수로의 자동 전환은 추후 고도화 |
| 피드백·재탐색 | 정보 보완·요구사항·가격 변경 시 필수 목록·필터·점수·최종 선택을 다시 평가. 기존 재탐색 한도 내에서 데이터 보완 후 Pass로 확인된 후보만 복귀 |

구현 시 다음을 확인한다.

- 밸런스·호환여유·소음이 점수 계산·가중합·축별 점수 및 기여도 설명에서 제거되고, 남은 세 축의 점수가 0~1인가.
- 가격이 참고 예산과 같으면 0.5이며, 참고 예산 이상에서도 가격이 높을수록 점수가 낮아지는가.
- 가격이 매우 낮거나 높을 때 각각 1과 0에 접근하고, 누락·0·음수·NaN·무한대 입력은 정상 점수로 처리하지 않는가.
- 기본·우선순위별·소음 민감 조건 모두 가중치가 음수가 아니며 합계가 1인가.

## 10. 단계별 적용과 검증 계획

| 순서 | 구현·검증 대상 | 완료 판단 |
|---|---|---|
| 1 | 필수 정보 목록·후보 보류·제외, 판매 단위·RAM 2개 구성, 세 축과 새 가격식·가중치·감점 제거·표시 | 필수 확인을 통과한 후보만 평가하고 `S_final = S_base`가 성립. 구성 가격·용량 중복 계산 없음 |
| 2 | 조합의 필수 호환 조건 확인과 전력·냉각·크기 여유 평가 연결 | 호환 조건 위반 1건 이상이면 무조건 탈락. 일부 정보로 전체 통과 처리하지 않고 필수 미확인은 보류. 재탐색 종료·결과 채택에도 동일 조건 적용. ‘확인 필요’ 판정 세분화는 추후 고도화 |
| 3 | 원래 추천 점수에 따른 최종 조합 선택 | 동일 구매 대상 슬롯의 유효 조합에서 점수 합이 높은 순으로 선택하고 동점이면 낮은 총가격·제품 키 순서 적용. 광고 우대 없음 |
| 4 | API·저장·설명·화면과 피드백 재탐색 | 적합도·검증 점수가 구분되고 동일 정책 버전으로 재현 가능. 광고 우대 전용 기능 구현 제외 |
| 5 | 고정 시나리오·시뮬레이션·회귀 비교 | 예산·최소 성능·호환 조건 위반 없이 새 점수식·가중치·후보 제외 정책의 영향과 기존 대비 품질 변화를 확인 |

후보 제외 정책은 추천 결과가 줄어드는 영향까지 검증한다. 동일 요청·카탈로그에서 기존 정책, 필수 정보 확인 정책, 새 점수식까지 적용한 결과를 나누어 비교하고, 슬롯별 Pass·Pending·Fail 수, 누락 항목별 보류 사유, 데이터 보완 성공률, 정상 추천 가능 비율, 후보 부족 비율, 최종 필수 조건 위반 여부를 기록한다. 일부 필수 정보 누락·모든 후보의 동일 필수 정보 누락·Pass 소수·전부 Pending·전부 Fail·선택적 정보만 부족·조합 필수 정보만 부족·검증 점수 통과지만 필수 호환 미확인·정보 보완 후 복귀를 고정 시나리오에 포함한다. 추천 가능한 결과만 집계해 후보 부족을 숨기지 않는다.

추후 고도화는 제8.2~8.6절의 광고 가산점과 관련 탐색·저장·표시·검증, ‘확인 필요’ 사유·중요도에 따른 판정 세분화, RAM의 다른 개수와 기존 부품 재사용, 벤치마크 기반 성능, 비교 가능한 소음 측정, 예산 배분·검증 기준의 실증 보정, 주변기기 경로의 별도 점수·광고 정책 확장으로 관리한다. 예산 배분은 기존 비율을 잠정 기준으로 유지한다. 이번 문서 수정은 구현 계획이며 실행 코드·설정·DB를 변경하지 않는다.
