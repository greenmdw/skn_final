01

화면 목록과 표면

Phase A는 화면(page)이 아니라 표면(surface) 단위로 센다. 고객사 CRM 위에 얹히는 구조라 페이지 이동이 없고, 네 개의 표면이 상태에 따라 나타났다 사라진다.

핀표면기본 상태여는 조건담는 것
1상주 캐릭터항상 표시 · idle—에이전트 상태(idle / working / alert) + 미확인 배지
2토스트 알림숨김서버 SSE 이벤트 수신한 줄 요약 + 행동 유도. 12초 후 자동 접힘, 배지는 남음
3채팅 패널숨김캐릭터 · 토스트 클릭자연어 질의응답, 근거 링크, 추천 질문 칩
4구역 대시보드폭 0어시스턴트의 open_dashboard_view tool 또는 사용자 클릭협상 진행 · 재고/ATP 2개 뷰
5확정 바숨김후보 순위표에서 한 건 선택선택 요약 + 확정 버튼 (사람의 유일한 실행 지점)
화면 설계의 제1원칙 확정 버튼은 대시보드에만 있다. 채팅 패널에는 어떤 실행 버튼도 두지 않는다. 대화로 실행이 되면 "무엇을 승인했는지"가 로그에 남지 않기 때문이다. 챗봇은 대시보드의 해당 뷰를 열어줄 뿐이며, 이것이 §5 tool 권한 설계와 화면이 일치하는 지점이다.
02

상주 캐릭터 · 토스트

캐릭터는 장식이 아니라 에이전트의 상태 표시기다. 세 상태가 형태로 구분되어야 하며, 색만으로 구분하지 않는다(움직임 + 배지 + 색).

상태data-state형태발생
대기idleteal · 3.6초 주기 호흡 애니메이션기본
작업 중workingamber · 회전. 협상 라운드가 도는 동안 유지tool 호출 시작 ~ 결과 수신
알림 있음alert3회 점프 + 붉은 배지(미확인 수)SSE 이벤트 수신

토스트는 한 줄이어야 한다. 판단에 필요한 숫자 하나(약속 가능 수량)와 행동 유도만 담고, 근거·계산 과정은 채팅 패널로 미룬다. 토스트에 표를 넣으면 CRM 작업을 가린다.

03

채팅 패널

답변에는 반드시 근거가 붙는다. 숫자만 답하는 말풍선은 금지이며, 계산 과정 블록과 원본 레코드 링크를 함께 낸다. 산출할 수 없는 질문에는 추정하지 않고 "데이터가 없다"고 답한다.

요소규칙데이터 출처
봇 말풍선본문 1~3줄 + 필요 시 계산 블록 1개어시스턴트 응답
계산 블록등호가 보이는 한 줄 수식. 결과값만 강조색get_available_to_promise
근거 링크레코드 ID를 점선 밑줄로. 클릭 시 좌측 CRM에서 해당 레코드 열림get_sale_orders
추천 질문 칩최대 3개. 사용한 칩은 비활성. 자유 입력은 Phase B대화 상태별 고정 목록
상태 표시● ready / ● thinking / ● negotiatingtool 호출 상태
Phase A 제약 자유 텍스트 입력창은 넣지 않는다. 5분 데모에서 오타·예상 못 한 질문 하나가 전체 흐름을 무너뜨린다. 추천 질문 칩 3개로 고정하고, 자유 입력은 Phase B에서 연다.
04

구역 대시보드 — 2개 뷰

대시보드가 열리면 CRM은 줄어들 뿐 사라지지 않는다. 왼쪽 CRM은 계속 조작 가능해야 하고, 확정 직후 좌측에서 반영 결과가 보여야 한다 — 데모 3:40 컷이 이 동작 하나에 걸려 있다.

뷰구역내용데이터 출처
협상 진행요청 요약품목·수량·상한가·최대 납기·우선순위negotiate_procurement 인자
라운드 스트림노드별 OFFER / REJECT / ACCEPT를 시간순 추가. 라운드 구분선 삽입SSE ← broker 로그
셀러 노드 뷰데모 전용. 셀러 로그와 브로커 로그를 나란히 놓아 floor_price가 한쪽에만 있음을 보임seller_logs / broker_logs
후보 순위표단가·납기·사양 유사도·예상 마진 + 선택 버튼SETTLED payload
재고 · ATP4칸 요약현재고 / 예약 / 입고예정 / 약속 가능 — 마지막 칸만 강조get_available_to_promise
계산 전개수식 한 줄 + 예약 건별 레코드 링크stock.quant · sale.order
입고 일정기준일 이후 도착분은 붉은색으로 "기한 초과" 표기purchase.order

순위 1위가 정답이 아니다. 프로토타입에서 시스템은 price_min 가중치로 오퍼렛을 1위로 올리지만, 고객 납기가 D+25라 28일이 걸리는 오퍼렛은 실제로는 쓸 수 없다. 담당자가 2위를 고르는 이 장면이 "에이전트는 안, 결정은 사람"의 가장 좋은 증거다 — 순위표는 정렬된 후보 목록이지 결론이 아니다.
