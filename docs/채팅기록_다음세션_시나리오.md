## 2. 전제: RAG를 어디에 쓰나

지금 RAG는 Bedrock 임베딩 + 메모리 안 코사인 검색이고 벡터 DB는 없다(`src/rag/`).
한 사용자의 과거 대화는 몇 세션 분량이라 **그 자체를 RAG로 검색할 만한 양이 아니다.**
과거 기록은 SQL로 꺼내 LLM이 요약하고, RAG는 리뷰·가이드·게임 요구사양 같은
**외부 근거 검색**에 쓰는 조합이 자연스럽다.

## 4. 선행 작업끼리 겹치는 부분

- **과거 기록 읽기 쿼리:** A1~A3, B1~B3, C3이 모두 기대는 기반. 가장 먼저 만들 것
- **이벤트 `user_id` 채우기 + 선호 저장소:** B4, A4, D5가 기댐
- **같은 세션 안의 일(다음 세션과 별개로 진행 가능):** C1, C2
- **범위와 무관하게 필요한 것:** 결과 화면 채팅을 서버에서 복원하는 화면 작업, 대안 적용 이벤트 기록

## 5. 제안 순서

A1 → B1 → B2. A1이 과거 기록 읽기 기반을 만들고, B1·B2가 그 위에 RAG를 얹는다.
B4는 이벤트 `user_id` 작업 뒤에 붙인다.
