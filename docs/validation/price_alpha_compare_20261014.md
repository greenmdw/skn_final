# 가격 축 alpha 1 → 2 비교 검증

작성일: 2026-10-14
상태: 가격 축을 `1 / (1 + (P/B)^α)`로 바꾸고 α=2를 잠정 적용한 뒤의 비교(`score_method` `pc-fit-v3`, 점수식 설정 `recommendation-engine-v1-20261014`). 근거와 남은 검증은 [검증 방향 종합안](../추천점수_예산배분_검증방향_종합_20261014.md) 4.2절(E3)이다.

표의 수치는 `scripts/engine_policy_report.py` 출력과 같은 두 덤프의 재집계다. 원본 덤프는 같은 폴더의 `engine_price_alpha1_20261014.json`, `engine_price_alpha2_20261014.json`이다.

## 1. 실행 방법

개발 DB `truefit`을 읽기만 했다(읽기 전용 트랜잭션, run 저장 없음, LLM 없음). 요청은 [엔진 정책 비교 검증](engine_policy_compare_20261012.md)과 같은 126개다. α=1은 저장소 설정을 고치지 않고 `--engine-config`로 별도 설정 파일(`alpha: 1`, `config_version: experiment-alpha-1`)을 넘겼다.

```bash
MOCK_MODE=1 CATALOG_SOURCE=db PYTHONPATH=. UV_CACHE_DIR=/tmp/uv-cache \
  uv run python scripts/engine_policy_compare.py --engine-config <alpha 1 설정 YAML> \
  --out docs/validation/engine_price_alpha1_20261014.json
MOCK_MODE=1 CATALOG_SOURCE=db PYTHONPATH=. UV_CACHE_DIR=/tmp/uv-cache \
  uv run python scripts/engine_policy_compare.py --out docs/validation/engine_price_alpha2_20261014.json
PYTHONPATH=. UV_CACHE_DIR=/tmp/uv-cache uv run python scripts/engine_policy_report.py \
  --dump "alpha 1=docs/validation/engine_price_alpha1_20261014.json" \
  --dump "alpha 2=docs/validation/engine_price_alpha2_20261014.json"
```

- 결정성: 두 설정을 각각 두 번 실행해 `wall_ms`를 뺀 요청 결과가 같음을 확인했다.
- α 적용 확인: 같은 요청·같은 부품에서 α=1의 가격 점수 s₁로 x = 1/s₁ − 1을 구하면 α=2 덤프의 가격 점수가 1/(1+x²)와 일치한다.
- α=1 덤프는 2026-10-13 최종 덤프(`engine_policy_after_20261013.json`)와 125개 조합 중 124개가 같다. 다른 1건은 `extra|game|cyberpunk|2000000`의 GPU(RTX 5060 Ti → RX 7600)로, 가격식과 무관하게 그사이 바뀐 데이터·규칙의 영향이다. 아래 비교는 모두 같은 날 같은 DB에서 만든 두 덤프끼리의 비교다.
- 두 덤프는 저장소 작업 트리에 미커밋 변경이 있는 상태(`git_dirty=true`, 커밋 2cb8094a 기준)에서 만들었다.

## 4. 해석

**예산 사용률은 2.6%p 내려갔다.** 정책 변경 전 기준선에서 v12로 올라간 폭(같은 108건 68.76% → 76.21%)의 약 3분의 1을 되돌린 수준이다. 금액 환산(성능 1등급이 참고 예산의 31% → 14%)에 비해 효과가 작은 이유는 두 가지다.

- **예산이 빠듯한 요청은 총예산 검사가 먼저 묶는다.** 100만 원 요청은 거의 변하지 않았고(98.7% → 98.5%), 변화는 350만 원(55.7% → 50.2%)에 몰렸다.
- **성능 우선은 여전히 예산 대부분을 쓴다**(92.5% → 90.4%). 성능 가중치 0.60에서는 α=2에서도 1등급이 참고 예산과 같은 금액(1.00B)이라, 총예산 안에서는 성능을 고르는 경향이 유지된다. GPU 등급은 그대로(7.54)이고 CPU만 내려갔다.

**게임 용도에서 CPU 과투자가 줄었다.** 게임 요청의 평균 CPU 등급이 8.62에서 7.12로 내려갔고 GPU 등급은 6.62로 같다. 게임 배분의 CPU 참고 예산(18%)이 작아 α=1에서는 비싼 CPU도 가격 점수를 크게 잃지 않았는데, α=2에서는 참고 예산을 넘는 CPU가 더 빨리 불리해진다. 순위 상위 5개 밖에서 선택된 CPU도 27건에서 14건으로 줄었다.

**저소음 우선의 변화가 가장 크다**(81.0% → 72.7%). 저소음 우선은 가격 가중치가 0.40으로 낮고 리뷰가 0.35로 높아 α=1에서 리뷰 차이로 비싼 부품을 고르기 쉬웠다(금액 환산 리뷰 +0.1 = 0.42B → 0.19B). 이 결과가 정숙성 개선에 따른 것은 아니다(검증 방향 종합안 3.3).

**소음 민감 여부만 다른 60쌍에서 선택이 다른 쌍이 1쌍에서 13쌍으로 늘었다.** 바깥 가중치는 두 경우 모두 같으므로(0쌍), 이 차이는 리뷰 내부의 정숙성 α가 순위를 바꾼 결과다. 참고 예산 근처에서 가격 점수 차이가 커지면서 접전이 다르게 갈린 것으로 보이며, 이 덤프만으로 원인을 분리하지는 않았다. 13쌍의 선택이 실제로 더 조용한 부품인지는 정숙성 근거가 부족해(선택 부품의 정숙성 기여 비율 noise=0 193/513, noise=1 180/480) 판단할 수 없다.

**가성비 우선은 거의 같다**(61.2% → 61.6%). 가격 가중치 0.55가 이미 커서 α를 올려도 추가로 아낄 여지가 작다. CPU 등급은 6.38에서 6.77로 올랐고 GPU 등급은 5.85에서 5.50으로 내려갔다. 참고 예산 근처에서 가격을 더 엄격히 보면서 CPU·GPU 사이의 배분이 바뀐 것으로, 개선 여부는 이 덤프로 판단할 수 없다.

**확대 탐색이 55건에서 69건으로 늘었다.** 상위 후보끼리 예산·호환 조합을 만들지 못하는 경우가 늘었다는 뜻이다. 처리 시간은 두 설정을 동시에 실행해 측정 조건이 같지 않으므로 비교하지 않는다(α=1 p50 504ms, α=2 p50 530ms).

## 5. 판단과 남은 일

α=2는 하드 조건(정상 추천의 필수 조건 위반 0건, 예산 단조성, 정상 추천 비율 유지)을 모두 지켰다. 예산 사용률을 낮추는 방향도 의도와 같다. 잠정값으로 유지할 수 있다.

다만 다음은 이 비교로 확인되지 않는다.

- **예산 배분 하한 점검(종합안 4.2.1)은 아직이다.** α=2에서는 후보 가격이 참고 예산에서 멀면(대략 3B 이상) 가격 축이 오히려 더 완만해진다. 슬롯별 최저 적격 가격과 참고 예산의 비율을 확인해야 α=2를 확정할 수 있다.
- **선택이 더 좋아졌는지는 알 수 없다.** 예산 사용률과 등급은 품질 지표가 아니다. 외부 정답(벤치마크·맹검 비교)이 필요하다.
- **α=1.5·3과 배분 ±5%p의 조합 실험**은 하지 않았다. `--engine-config`로 같은 방식으로 실행할 수 있다.
