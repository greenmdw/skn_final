## 2. 요청 입력과 선택 정책

초기 profile_version은 `review-profile-v1-20261002`로 지정한다. 분석 버전은 위 확인 버전을 명시적으로 선택한다. 이 문서는 이후 YAML 설정과 순수 계산 서비스의 구현 계약이다.

- `config/categories/computer.yaml`: purpose 허용값은 `game`, `creation`, `office`, `study`, `other`. purpose는 필수 입력이며 defaults에는 없다.
- `src/engine/stage1_intent.py`는 defaults/assumed/confirmed를 병합한다. 필수 purpose는 가정하지 않는 계약이다. 리뷰 프로필은 assumed_keys 등 출처 정보를 함께 확인하여 명시 여부를 보존한다.
- `stage3b_rank.py`는 성능 계산에 purpose 누락 시 game을 쓰지만, 이를 리뷰 조건의 명시적 게임 요청으로 취급하지 않는다. 기존 성능 기본값은 이번 작업에서 변경하지 않는다.

- 현재 슬롯에는 작업 부하 종류, 안정성 평가 기간, 팬 RPM의 전용 구조화 필드가 없다. 초기 구현은 자유 텍스트나 extra에서 임의 추론하지 않는다. 명시적 세부 조건 선택은 검증 가능한 정규화 입력과 출처가 도입된 후 연결한다.

## 4. α 및 중립 처리

- 부품별로 이 버전에 등록된 고유 aspect_code마다 b=1을 배정한다. 조건별 규칙 수나 관측 수를 b에 반영하지 않는다.
- priority=quiet 또는 noise_sensitive=true이면 등록된 fan_quietness/coil_quietness/pump_quietness만 b=3으로 바꾼다. 두 조건이 동시에 있어도 3이며 중복 증폭하지 않는다.
- α=b/Σb. 동일 요청·상품 유형의 모든 후보에 같은 α와 선택 조건을 사용한다.
- 주변기기의 typing_noise/unwanted_noise는 초기 quiet 배수 대상이 아니므로 b=1을 유지한다. 주변기기 외부 리뷰 가중치도 0을 유지한다.
- 해당 조건의 상품 집계가 없으면 Q=0.5, α는 유지한다. 다른 조건으로 fallback하지 않는다. 펌프 없는 쿨러도 별도 세부 프로필을 만들지 않는다.
- 규칙 누락, 집계 근거 없음, product_id 없음은 별도 이유로 전달한다. DB 실행의 식별자 누락은 데이터 진단 대상으로 보고하고 product_key로 추측하지 않는다. product_id 없는 명시적 데모 후보는 중립을 허용한다.
- 균형 P=N 및 mixed-only도 Q=0.5일 수 있으므로 값만으로 근거 없음을 판단하지 않는다. counts/rule_id/aggregate_id/member를 함께 전달한다.

| 유형 | 기본 속성 수 | 기본 α | quiet 적용 속성 | quiet의 Σb |
|---|---:|---|---|---:|
| case | 4 | 1/4 | 없음 | 4 |
| cooler | 4 | 1/4 | fan_quietness, pump_quietness | 8 |
| cpu | 3 | 1/3 | 없음 | 3 |
| gpu | 5 | 1/5 | coil_quietness, fan_quietness | 9 |
| keyboard | 5 | 1/5 | 없음 | 5 |
| mainboard | 5 | 1/5 | 없음 | 5 |
| monitor | 5 | 1/5 | 없음 | 5 |
| mouse | 5 | 1/5 | 없음 | 5 |
| psu | 3 | 1/3 | coil_quietness, fan_quietness | 7 |
| ram | 2 | 1/2 | 없음 | 2 |
| speaker | 5 | 1/5 | 없음 | 5 |
| ssd | 3 | 1/3 | 없음 | 3 |

quiet 적용 속성은 α=3/Σb, 나머지는 α=1/Σb다. 예: GPU 기본 α=1/5, quiet이면 fan/coil 각 3/9, 나머지 각 1/9. R=ΣαQ이며 계산은 등록 k를 사용한다.

## 5. 마이그레이션 정합성과 후속 작업

- 실제 파일 0000~0008의 9개 마이그레이션 모두 DB 적용 기록이 있으며 파일 체크섬과 일치한다. 추가/누락 적용 기록도 없다.
- 0008_review_aspect가 정의한 7개 테이블은 위 건수 SELECT로 존재를 확인했다. 임베딩 생성은 이번 범위 밖이다.
- tests/test_schema_reduction.py의 9개 기준과 일치한다. AGENTS.md의 8개 목록 및 자동 설정 설명의 4개 표현을 9개로 정리했다. SQL 파일과 DB는 변경하지 않았다.
- 집계/멤버는 현재 0건으로, 실데이터 리뷰 점수 연결 준비가 완료된 상태는 아니다. 집계 CLI 구현과 apply가 다음 단계다.
- 전체 집계 미생성·부분 생성과 개별 상품의 무관측을 구별하는 준비 상태 계약, DB 오류 시 자동 데모 전환 방지 정책은 엔진 연결 전에 구현해야 한다. 이 문서는 새 이력 테이블이나 준비 상태 저장 방식을 확정하지 않는다.

## 6. 이번 작업의 검증

DB는 하나의 읽기 전용 스냅샷에서 건수·버전·상품 유형·원문 연결·등록 규칙·마이그레이션 체크섬을 확인했다. 매핑표는 DB 스냅샷에서 생성하여 49개 속성과 102개 등록 규칙을 대조했다. 문서 변경만 수행했으므로 pytest 및 집계 apply는 실행하지 않았다. 후속 코드 구현 완료 검증에서는 AGENTS.md의 TRUEFIT_REQUIRE_TEST_DB=1 격리 DB 테스트를 따른다.
