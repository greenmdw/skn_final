# 리뷰 점수 실데이터 적용 및 smoke 결과

2026-10-02에 `localhost:5432/truefit`의 `review-aspect-v6-prod-20261002` 버전을 대상으로 유지보수 구간 적용을 수행했다. 외부 호출 없이 집계 CLI만 `--apply`로 한 번 실행했고, 이후 감사와 추천 smoke는 PostgreSQL read-only 트랜잭션으로 처리했다. 문서·규칙·관측·catalog·추천 실행을 쓰거나 변경하지 않았다.

## 집계 적용과 감사

적용 직전 원본은 규칙 102개, 관측 3,676개(P 2,841/N 570/mixed 265), 연결 문서 2,384개였으며 대상 집계/member는 없었다. dry-run은 833개 group insert를 예상했다. 적용 후 규칙·관측·문서 수는 그대로이고 집계 833개와 member 3,676개가 만들어졌다. 집계 방향 합계는 P 2,841/N 570/mixed 265다.

별도 read-only 전수 감사에서 원본 group과 집계의 누락·초과, Q/k 불일치, member 누락·중복, 상품/규칙 연결 오류, 합성 문서 연결은 모두 0건이었다. 833개 group의 member 수는 원본 관측 수와 일치했다. Q 계산 최대 차이는 `0E-20`이었다. 다른 분석 버전의 집계/member는 0개였다. post-commit CLI dry-run은 833개 group 모두 unchanged로 판정했고 insert/update/delete는 각각 0이었다.

문서·규칙·관측·catalog·추천 실행/profile의 사전/사후 fingerprint 27개는 모두 같았다. migration 수는 9로 유지됐고 추천 실행/profile 행 수는 각각 1/0으로 변하지 않았다. 사후 감사는 커밋된 별도 snapshot에서 성공했다.

## 요청별 read-only smoke

실제 catalog의 GPU 후보 43개를 대상으로 공유 scorer와 stage3b 랭커를 호출했다. 아래 점수는 해당 요청에서 랭커가 고른 후보의 최종 점수다. `manual raw`는 가격·성능·밸런스·리뷰·호환·소음 축과 기존 penalty/gap/RAM 정책을 합산한 반올림 전 값이며, `manual rounded`와 실제 랭커 점수가 모두 일치했다. `리뷰 Δ`는 `w_review × (R − 0.5)`로, neutral reference 대비 리뷰축만의 반올림 전 차이다.

위 GPU 조건별 smoke는 GPU 43개만 랭킹했다. 독립 점수 손검산 설정은 `targets={"GPU": {}}`, 예산 2,000,000원, GPU 배분 0.6(슬롯 예산 1,200,000원)이므로, 그 최종 점수는 실제 8부품 견적의 점수와 비교하지 않는다. 네 요청별 손계산은 해당 동일 설정에서 각기 선택된 GPU의 기존 ranking weights와 가격·성능·밸런스·호환·소음·gap/penalty 정책을 사용했다.

또한 actual catalog GPU 후보 43개 전부에 대해 `game/performance` 요청 profile과 DB의 원 P/N/mixed/k 값으로 Q 및 `Σ(α×Q)`를 별도로 재계산했다. R 계산 오차가 `1e-12`보다 큰 후보는 0개였고, R 범위는 0.500000–0.598413, `w_review`는 0.2였다.

## 범위와 재현성

현재 schema에는 집계 완료 manifest가 없다. 이번 전수 감사로 이 버전의 현재 원본 group과 집계/member를 대조했지만, 이후 원본 관측 변경을 자동 탐지하거나 `global_completeness_verified=true`를 선언하지 않는다. 런타임 저장소의 전역 완전성 제한은 그대로 남는다.

재현에 사용한 CLI는 다음과 같다. `--apply`는 위 유지보수 작업에서 한 차례만 실행했다.

```bash
PYTHONPATH=. UV_CACHE_DIR=/tmp/uv-cache \
PGOPTIONS='-c lock_timeout=5000 -c statement_timeout=120000' \
uv run python db/rebuild_review_aspect_aggregates.py \
  --analysis-version review-aspect-v6-prod-20261002 --apply
```

최종 idempotence 확인은 read-only mode로 별도 수행했다.

```bash
PYTHONPATH=. UV_CACHE_DIR=/tmp/uv-cache \
PGOPTIONS='-c default_transaction_read_only=on -c lock_timeout=5000 -c statement_timeout=120000' \
uv run python db/rebuild_review_aspect_aggregates.py \
  --analysis-version review-aspect-v6-prod-20261002
```

smoke는 `PGOPTIONS`로 transaction read-only, 5초 lock timeout, 120초 statement timeout을 강제하고 `MOCK_MODE=1`로 실행했다. 코드 검증은 격리 test DB에서 별도로 수행했다.

단계 7 전체 pytest는 격리 DB에서 `1651 passed, 1 failed, 3 skipped, 2 xfailed`였다. 유일한 failure는 기존 `test_plan_review_mix`가 기대하는 `outputs/review_counts_grouped_20260925/review_count_plan.json` 누락이며, 이 실데이터 적용·smoke 변경과 무관한 알려진 문제다. 파일은 만들거나 변경하지 않았다.
