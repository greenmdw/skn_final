# 컴퓨터 부품 리뷰 평점 적재·표시 계획

작성일: 2026-10-19
상태: **1~6단계 구현 완료(미커밋), 전체 테스트 통과(2026-10-19, 4027 passed).** 0단계는 ad81ba7a로 커밋했다. 개발 DB 적용과 화면 확인(5절 3·4·6번), 번들 재배포(7절 2번)는 남았다. D1·D3·D4는 권장대로, D2는 "건수와 상관없이 늘 평균을 내고 건수를 함께 보인다"로 2026-10-19에 확정했다. 화면(`web/`) 수정은 이번 작업에 한해 사용자 허락(2026-10-19)을 받아 이 계획 범위에 넣었다. 프론트엔드 요청 문서는 따로 만들지 않는다. 구현 중 확인: 스피커 리뷰 1건의 원본 평점이 0이라 null로 둔다(평점 있음 5,571건).

## 1. 목적

새 컴퓨터 본체 추천 결과 화면의 부품별 "리뷰" 칸에 리뷰 개수만 나오고 평점이 비어 있다. 원본 리뷰 파일에는 별점이 있는데 DB 적재 과정에서 빠졌다. 이 별점을 DB에 넣고, 추천 결과·제품 비교·리뷰 요약에 **수집처 평균 별점과 그 평점 건수**를 보여 준다.

> **이번에 내는 값은 "수집처(다나와)에서 구매자가 매긴 별점의 단순 평균"이다.** 조작 리뷰를 걸러 낸 "검수 후 평점"(`rating_refined`)이 아니다. `rating_refined`는 판정기가 없으므로 지금처럼 계속 null로 둔다.

## 5. 검증

1. AGENTS.md의 기본 명령으로 전체 테스트를 돌린다(`TRUEFIT_REQUIRE_TEST_DB=1`, `-m "not llm_live"`).

## 6. 범위 밖

- 주변기기(모니터·키보드·마우스·스피커) 추천 결과의 평점 표시: 컬럼과 적재는 같이 되지만, 주변기기 결과 응답(`peripheral_payload.py`)과 `PeripheralResultSection` 화면은 이번에 고치지 않는다.
- 견적 점검 화면의 교체 후보(`quote_alternatives.py`): `review_brief()`를 쓰므로 API에는 평점이 실리지만, 그 화면의 표시는 고치지 않는다.
- 작성일(`posted_at`) 적재(D3), 평점의 순위 반영(D4).
- `_db_backed_analysis()`의 같은 `DATABASE_URL` 조건: 그 함수가 읽는 `evidence.review_aggregate`가 비어 있어 지금은 영향이 없다.
- 평점 분포(`distribution_raw`): 화면이 읽지 않으므로 이번에 채우지 않는다.

## 7. 배포 순서와 위험

| 순서 | 내용 |
|---|---|
| 1 | 0단계 커밋 |
| 2 | 새 번들을 만들어 비공개 데이터 채널에 올리고 팀에 알린다. **옛 번들을 가진 사람은 3단계가 들어간 뒤 `setup_all`·DB 테스트가 실패한다**(옛 번들 오류 메시지가 원인을 알린다) |
| 3 | 1~6단계를 한 브랜치에 커밋한다. 백엔드(1~4단계)와 화면(5단계)은 따로 커밋해 되돌리기 쉽게 한다 |
| 4 | 배포 DB: 마이그레이션(`0020`) → 새 번들로 `python db/seed_review_corpus.py --load-bundle` → API 재시작. Docker 이미지가 `data/`를 복사하므로, 이미지에 번들을 넣는 환경이라면 이미지를 다시 빌드한다 |
| 5 | 화면 빌드를 배포한다. API의 새 필드는 추가만 했으므로 4와 5의 순서가 바뀌어도 깨지지 않는다(새 화면 + 옛 API면 리뷰 개수만 보인다) |

- **변별력:** 5점이 89%라 대부분의 부품이 ★4.8~5.0으로 보인다. 이 평점은 고르는 기준이라기보다 "구매자들이 대체로 만족했다"는 참고 정보로 표시한다.
- **건수가 적은 평균(D2):** 226개 중 85개가 평점 5건 미만, 54개가 3건 미만이다. 이들도 평균이 나가므로 건수 표시가 빠지면 오해를 부른다. 5단계의 "평균 옆 건수 필수" 조건을 화면 확인(5절 6번)에서 꼭 본다.
- **출처 편향:** PC 부품 평점은 모두 다나와 한 곳에서 왔다. 화면 라벨과 `data_notice`에 출처를 밝힌다.
- **비공개 데이터:** 평점은 리뷰 본문보다 민감하지 않지만, 같은 번들 안에 있으므로 Git에 올리지 않는 규칙을 그대로 따른다.
